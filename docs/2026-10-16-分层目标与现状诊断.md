# 分层目标与现状诊断实施说明

平台主线为：各规模目标 → 可编辑系统架构与故障归属 → 分层损失预算 → 固定现状评估 → 各规模薄弱点与贡献排序 → AGREE改进要求 → 用户独立执行复评 → 横向比较与交付。

第二步新增架构图、层级编辑、逐事件归属与共同依赖；第三步新增分层目标预算，支持暂不分配、均分、权重及AGREE损失预算适配。功能分组模板和均分是暂定设计参照，不宣称已确认部署架构或专家模块指标。多规模权重可用scaleWeights设置。

分层诊断复用原仿真账本，父层汇总子层，每个根故障只归属一次。未映射故障与公共开销都有显式节点。总损失、分层损失及预算均可核对守恒；不改变主可用度计算。中断MTBF、其他类型事件间隔、恢复停机/次和等效损失/事件分别展示，避免把污染、回滚和保存损失错误压缩为物理MTTR。

结果新增分层诊断视图：架构节点目标与实际、规模×子系统热力图、统一刻度的各规模Shapley排序、故障及机制覆盖证据。报告保留相同图表和细节；改进评估重新生成该方案的分层诊断，比较报告列出各轮主要薄弱点。

AGREE设计责任先追溯到实际层级、逐事件保护范围及可改善的损失项，再以第一轮Shapley为重要度参考。未覆盖责任单列，不把整个系统损失任意摊给无关措施。参数仍由条件响应与总目标约束反推，规划不算正式复评，不改变第一轮；各规模不合成最严共同要求。

输入修改恢复规则已细分：架构结构/故障归属从第二步复核，预算方法/权重/重要度从第三步复核。现状结果、独立改进与历史报告保持各自输入快照。Skill 0.3.2补充架构诊断读法、计量边界、责任追溯和工具操作说明。
