# 前端流程优化与用户走查

本轮针对固定流程导航、信息密度与用户操作连续性，沿真实界面执行任务创建、参数输入、求解、报告和回代。数值模型与指标口径沿用《2026-10-12-目标达成审计》，本轮没有修改公式或专家数据。

## 修改与设计理由

- 六阶段以序号、箭头、当前高亮和确认状态连续呈现。步骤条与上一步、确认/下一步合并为一个固定栏；手机和 Agent 展开后的窄工作区采用横向步骤条，当前步骤随选择或宽度变化自动进入可见区域。
- 浏览步骤会展开相应折叠表单、定位并聚焦内容；定位偏移按固定栏实际高度计算。返回已确认步骤时显示“下一步”，只浏览、不再次签认；正在保存时禁用重复确认。
- 详细说明、执行版本和过程产物移入“步骤说明与记录”，支持键盘 Escape 关闭并恢复焦点。Agent 待审核提示仍保留在固定栏内。错误也在固定栏显示，避免远处的错误提示被漏看。
- 审核表单重排为目标、故障证据、预算与措施、参数、运行。采样、复核和恢复顺序归入参数核对，首屏保留目标与规模；区域编号与流程一致。
- 切页、切换指标和产品场景回到页首。未生成结果时，交付步骤给出明确的计算入口。加载最新任务设计时重新装载审核表单，避免外层版本与表单残留草稿不一致。
- 传统系统直接进入专业工具，不再显示与其表单不对应的训练六阶段导航。传统系统仍是独立求解实验，没有因此新增正式设计闭环。
- 删除旧步骤条和大操作框的无用样式，收紧任务标题、指标切换和保存提示占用空间。

## 浏览器走查矩阵

| 用户路径 | 检查点 | 自动化证据 |
| --- | --- | --- |
| 任务管理与迁移 | 新建、重命名、复制、归档/恢复、任务隔离、任务包导出/导入 | tasks、journey、workflow-agent |
| 审核主流程 | 目标与多规模、CORE-hard 替换、预算、参数、四步确认、正式运行、结果核对、交付、建议回代重确认 | audit |
| 旧 V4 设计流程 | 目标/窗口、预算、机制、输入变更、正式阶段绑定、草稿刷新恢复 | ux、tasks、workbench |
| 输入与来源 | JSON 文件确认及场景映射；CSV 资产草稿；晚到映射不能覆盖另一文件 | workbench、ux |
| 资产库 | 新建、校验冻结、复制版本、旧版本查看、绑定与手工修改解绑 | workbench、ux |
| 方法与工具 | 指标分配、RBD、FTA、BDD、CTMC、比较、搜索、敏感性、Shapley、事件频率估计均从按钮实际执行，等待成功并核对报告归属 | journey（含 Equal、ARINC、AGREE、Availability 四个入口）；ux 补充同指标分配比较 |
| 实验与报告 | 运行历史、原输入重放、方案反馈保存与重新加载；HTML 下载、规模/事件筛选、展开明细、打印时恢复完整数据 | journey、audit |
| 取消与历史结果 | 取消新计算后保留上次完整结果，输入改变提示重算 | cancel、workbench |
| 人机协同 | Agent 产物进入相同阶段，人工权限门禁；原生 OpenCode 会话、模型选择与提供商表单 | workflow-agent、ux |
| 页面连续性 | 切页回到顶部、无结果引导、传统系统工具入口 | journey |
| 导航与可访问性 | 固定前后操作、五个连接箭头、自动展开、定位不遮挡、返回不重复确认、对话框 Escape 和焦点恢复 | navigation |
| 响应式 | 1440×1000 桌面、390×844 手机、Agent 展开变窄；页面无横向溢出，固定栏高度小于 180px | navigation、audit |

## 验收结果

- 发布检查 9 项通过：doctor、类型、lint、领域/集成测试、Web 构建、MCP 构建、浏览器流程、发布包和同机异目录迁移。
- Vitest：41 个文件、213 项通过；包含真实 CTMC Python 调用与专家默认口径复现。
- 最终 Playwright：25 项全部通过，没有跳过原生 OpenCode 用例；覆盖十种专业工具及四个分配入口。
- Python CTMC：5 项通过。最后的自适应步骤栏调整后，另行完成类型、lint、Web/MCP 构建和完整浏览器回归。
- 实测固定栏高度：1440px 桌面为 124px，390px 手机为 134px。完整示例任务已通过六阶段并留存首屏、结果、手机和过程记录截图；示例使用 8 条轨迹，仅用于界面验收。
- 截图位于 `artifacts/frontend-review/`；机器记录见 `artifacts/release-validation.json` 与 `artifacts/frontend-review/validation.json`。

复验命令：

```bash
source scripts/cloud-env.sh
RELIABILITY_REQUIRE_CTMC=1 TEST_OPENCODE_URL=http://127.0.0.1:4096 pnpm verify:release
PYTHONPATH="$PWD/solvers/ctmc/.python-deps" python3 -m pytest solvers/ctmc/test_solver.py -q
```

原生界面用例需要先运行 `pnpm agent`；不配置模型密钥也能检查界面和同步链路。

## 范围边界

这些是浏览器操作、实现一致性与计算回归证据，不等于独立新用户研究。OpenCode 原生界面和任务协作链路可检查；本环境没有配置真实提供商密钥，不包含 GLM 实际推理或建议质量验收。内网实测数据、传统系统完整设计闭环等剩余目标见目标达成审计。
