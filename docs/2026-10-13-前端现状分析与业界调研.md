# ReMAP 前端现状分析与业界调研

调研日期：2026-10-13。基于本地 `1c36dd2`、实际工作台浏览、代码与回归测试，以及官方公开资料。已阅读会话“调研可靠性设计平台与AI Agent”，延续其中“工程对象工作台、视觉克制、智能有上下文、证据可复核”的方向。本轮未实机测试商业软件，不将公开产品宣传视为数值准确性或自主 Agent 能力认证。

## 现状与原因

| 观察                                                                        | 使用影响                                       | 本轮处理                                                                 |
| --------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------ |
| 当前第4步“参数核对”，正文仍从第1步评估范围开始，所有输入区连续排列          | 不知道当前该做什么，跳转后仍可能被其它步骤淹没 | 默认只显示当前步骤；提供“全部配置”供专家集中编辑                         |
| 任务栏、英文页眉、保存状态、模型设置、流程栏、表单标题重复描述上下文        | 首屏用于真正工作的位置不足                     | 单一任务标题层级；指标/模型信息压缩为上下文条，详细说明按需展开          |
| 结果中的预算、组合参数、损失、事件、收益、规模曲线、贡献和敏感性同时堆叠    | 结论与复核混在长报告中，难以比较               | 结果按“结论概览、方案收益、贡献分摊、风险与敏感性”切换；保留全部分析入口 |
| OpenCode 外围工具条有会话、新建、专题、同步、复制、设置、刷新等多个同级操作 | AI 对话被外围控制挤占；和当前流程的关系不明显  | 固定任务/当前步骤上下文；保留一个主要 Skill 动作，其它操作收进连接管理区 |
| 侧栏有固定“WORKSPACE / 001”和 Prototype 0.1，产品入口混合可用与待扩展状态   | 容易把假编号当实际任务信息                     | 改为明确资源分组和真实本地任务状态；未支持产品继续标明待扩展             |
| 任务主页各卡片重复多项管理按钮，任务多时缺少检索                            | 找任务和管理任务占据同样视觉权重               | 增加本地名称检索、匹配计数；突出打开任务，次要操作视觉降级               |
| 全局 CSS 经过多轮追加，App 同时负责状态、路由、表单与布局                   | 修改一处易影响其它页                           | 新样式限定工作台/组件作用域；按需提取纯展示组件，保留现有状态与 API 契约 |

先解决信息组织，再调整视觉。现有数值、任务隔离、人工确认、原生 OpenCode 和完整运行资产是必须保留的基础。

## 官方资料与可借鉴模式

| 参考                                                                                                                       | 已核实公开事实                                                          | ReMAP 的设计判断                                                             |
| -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------- |

| [Relyence：SmartSuggest Generate Suggestions](https://relyence.com/help/user-guide/smartsuggest-generate-suggestions.html) | FMEA 工作表右侧显示建议面板，可调宽度；用户勾选建议后插入               | 保留中间工程视图和右侧辅助；AI 输出通过现有任务资产/流程关联，用户保留确认权 |
| [LangSmith：Trajectories](https://www.langchain.com/blog/langsmith-trajectories-tracing)，2026-09-24                       | 用按时间排列的轨迹解释会话行为，再进入完整 trace 检查输入输出与运行细节 | 概览优先显示真实阶段和成果；完整事件/输入保持可追溯，不默认铺开              |

可靠性平台的专业视图、跨行业产品的信息层级和 Agent 平台的可读轨迹可以组合使用。上述来源不证明 ReMAP 应引入它们的 SDK，也不证明 AI 可代替专业求解或工程师确认。部分商业产品页面访问失败，未把不可核验的页面用作本轮实施依据。

## 方案比较

| 方案                                             | 收益                                       | 代价与风险                                   | 结论               |
| ------------------------------------------------ | ------------------------------------------ | -------------------------------------------- | ------------------ |
| A：仅调整色彩/间距                               | 快速改善外观                               | 不解决所有步骤、所有结果同时堆叠             | 不足以完成本轮目标 |
| B：当前步骤聚焦＋任务上下文＋结果视图            | 直接解决操作混乱，仍保留集中编辑和完整复核 | 需要验证步骤切换、编辑保留、自动执行和旧任务 | 本轮采用           |
| C：重建通用工程对象树/可视化画布/AI 变更审阅平台 | 可支撑长期全生命周期对象关联               | 涉及后端模型与数据迁移，超出前端优化边界     | 保留为后续独立功能 |

## 范围与验收

本轮覆盖任务主页、工作台壳层、六步骤专家配置、结果组织、OpenCode 外围操作和各资源页的一致性。传统/V4 工具入口继续保留，原生 OpenCode 的模型/API 设置继续使用本地官方界面。UI 视图状态不会写入设计输入，不改变输入修订、求解参数或用户签认。

验收以“当前步骤与正文一致、主要操作清楚、修改值切换视图后不丢、Agent 上下文准确、结果数值不变、附件可下载、桌面与手机无页面横向溢出”为依据。表格和图形可以在其自身容器内水平滚动。自动执行始终跟随真实步骤，不用假进度或固定提示冒充 Agent 工作。
