# 内外网单向迭代设计

状态：用户已批准实施。依据：上一轮内外网迭代建议及本轮“给一个计划，然后开始实施”。

## 目标与边界

外网维护可复用的可靠性核心、Skill、MCP、合成测试与工作台。经公司批准的软件版本单向进入内网；内网维护企业解析规则、真实故障/机制资产、配置、报告、运行轨迹和企业代码。内网代码和数据不向外同步，包括私有外网 Git、模型请求、日志和截图。只有按公司流程批准的独立合成问题描述可以在外网用于核心改进。

本次交付内网运行策略、企业映射适配接口、离线依赖准备和验证工具、内网开发指南。继续使用本机安装的 OpenCode。既有开发配置和任务保持可用，不把本机切换为企业环境。

## 结构

1. 通用核心仓库：外网开发，发布具有文件摘要的软件包。
2. 内网核心镜像：单向导入经审核的核心版本；内网补丁留在内网。
3. 内网适配仓库：独立本地适配模块，把企业文件字段映射为核心可校验的输入草稿；不修改求解器。
4. 内网资产与任务目录：由 DATA_DIR 指向核心源码目录之外；公共资产进入任务时仍需快照与版本绑定。
5. 内网模型：显式配置批准的模型地址与来源白名单。Agent 做小步骤编排；确认、单位校验、数值求解和状态转换继续由程序执行。

## 配置与控制

使用 RELIABILITY_ENV=internal、RELIABILITY_INTERNAL_CONFIG 指向本机 JSON。配置不含密钥；模型密钥引用环境变量。内网配置必须具有精确的批准 origin、OpenAI 兼容模型描述及固定适配版本（若启用适配）。OpenCode 与工作台 API 必须为本地回环地址。解析模型不得回落到外网默认地址。内网生成的 OpenCode 项目配置仅启用企业 provider 和本地可靠性 MCP，并关闭分享和自动更新。

应用校验不等于网络隔离：原生 Agent 全局配置、插件、模型目录更新、SDK 安装和工具命令仍需公司出口白名单/断网执行环境约束。上线需检查固定版本 OpenCode 的真实出站行为。不能声称靠一个环境变量保证零外传。

企业适配模块是管理员安装的可信代码，在 API 进程内运行，不是沙箱。输出必须经现有 mapConfirmedData 校验、预览和用户确认；记录适配标识、版本、源文件摘要。不得由 Agent 任意注册代码模块。

## 交付与验收

离线准备工具用独立 pnpm store 依据锁文件预取依赖；安装使用 --offline --frozen-lockfile 并核验锁文件摘要、平台和架构。准备包清单列明本机 Node/pnpm/OpenCode、Python/NumPy/SciPy 和浏览器测试运行时是否另行供给。没有供给的运行时不标记为完整离线环境。

外网执行通用回归和合成适配验收；内网另做真实格式、模型工具调用、数值金标准、资产权限、断网冷安装和网络出口验收。内网运行 export:release 应拒绝生成通用外网发布包；任务导出仍供内网迁移使用，不能当作外传许可。

本次不连接公司实际模型，不传入公司文件，不推送 Git，不部署公司基础设施。公司认证、出站网络策略和真实冷安装验收按指南由内网执行。
