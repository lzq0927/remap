# 评估系统使用指南：从任务到正式交付

更新：2026-10-11。适用本次任务隔离与统一流程版本。先使用示例熟悉操作，再换真实数据；示例结果不能作为产品达标证据。

2026-10-13 前端增加当前步骤聚焦、全部配置入口、结果目的视图、任务搜索及原生 Agent 控制分组，操作见[聚焦工作台使用指南](2026-10-13-聚焦工作台使用指南.md)。数值、权限和完整运行资产口径不变。

## 1. 启动

需要 Node.js 24+、pnpm 11。在软件目录运行：

```powershell
node scripts/launch.mjs bootstrap --install
pnpm run doctor
pnpm dev
```

另一个终端运行 `pnpm agent`，启动或复用本地安装的官方 OpenCode。开发界面默认 http://127.0.0.1:5173；生产使用 `pnpm build`、`pnpm start`，默认 http://127.0.0.1:4178。

通过 .env 的 OPENCODE_BIN/OPENCODE_URL 指定本机安装。脚本相对路径按软件目录解析，可用脚本绝对路径从其他目录启动。OpenCode 离线仍能手动求解。CTMC 另外需要 Python、NumPy、SciPy，可用 PYTHON_EXECUTABLE 配置。

## 2. 新建任务与界面关联

首页新建“万卡训练 · 演示基线”。每个任务有独立设计、输入、私有库、运行、报告、反馈、流程和会话。顶部显示任务及当前运行；右侧列表只显示本任务绑定会话，连接后自动创建或恢复具名主会话，也可新建专题。

| 页签 | 用途 |
|---|---|
| 可靠性设计与评估 | 目标、参数、机制、六阶段确认、训练结果 |
| 输入与来源 | 导入、修正提取、人工确认、字段映射 |
| 资产库 | 故障模式、机制、证据、模板、验证案例、事件台账与版本 |
| 方法与工具 | 指标分配、RBD、FTA/BDD、CTMC、比较、搜索等独立实验 |
| 实验与报告 | 回看运行及不可变输入快照、报告 |
| 连接与配置 | 本机连接与任务文件监听目录 |

任务 URL 含自己的 task ID，刷新可恢复，不同标签不共享全局当前任务。主页支持重命名、复制、归档、恢复、导入导出。复制任务适合另一个方案，重新确认流程与绑定会话；正在运行时先完成或取消，再复制/导出/归档。

## 3. 演示：手动完成万卡基线六阶段

默认专家口径衡量**期末保留的正确进度 / 窗口理想产出**，期末仍污染时保留最后干净检查点。历史模型 V4 使用 strict-clean-end：窗口结束仍有未恢复污染时整条轨迹交付清零。稳态可用度、无中断任务可靠度、MTBF 分开记录，不能混用。

新专家任务的可用度目标默认为：万卡 99%、十万卡 95%、二十万卡 90%、五十万卡 80%，需求达标汇总比较这四个规模，规模曲线另有1000卡参考点，不额外设定需求目标。对应专家外网基线的中断 MTBF 约为 30h、3h、1.5h、0.6h；MTBF 与需求目标独立记录，不能从 MTBF 单独推导可用度。各规模目标可编辑，切换卡数保留编辑值；旧任务沿用已保存目标，同规模不同方案和代际使用相同产品目标。

新任务默认“专家复现 · 正式审核”：主场景4000条、Shapley每子集2000条、敏感性每点2000条，三组种子及1.96正态近似与原报告一致。切换“快速试算”使用128 / 64 / 128条用于方向探索，保留已编辑的目标、证据和措施；报告依据冻结输入显示实际采样等级。

新任务的敏感性默认“专家原始13点”比较口径，固定50万卡：静默检出覆盖率与 step 上限在“静默检测＋step”情景下扫描，弹性协调暂停在弹性单项情景下扫描，扩展16点配置可补充漏检发现时延。也可编辑扫描卡数、采样量，或改为保持所选组合不变的扫描；每组报告标明情景和比较基准。旧任务保留历史五点扫描，不因升级自动改变输入。

主入口统一为“可靠性设计与评估”，不再区分两个并列流程。以下六步为历史 V4 兼容示例，仅需要复核旧模型时在“高级设置 → 历史模型”中选择；默认专家审核的六阶段操作见 [事件机制审核与指标分配](事件机制审核与指标分配.md)。

### ① 确认目标

选择 AI 训练集群，点击“万卡 · 99%”。设置 10000 卡、目标 0.99、窗口 24h、32 条轨迹、种子 9137、代际“演示代际”。这是小样本操作演示。

点击“确认并进入下一步”。查看某个阶段不等于确认，签认必须按顺序。

### ② 描述系统

核对结构、依赖、故障域、影响范围和恢复路径。参考 FIT 顺序是 HBM、GPU、网络、其他。FIT 是每十亿设备小时故障数，软件要注明调用、任务、作业小时等基准。

检查每服务器卡数、机架规模、检查点及污染状态。当前结构图为参数驱动简图，未核对的架构输入不能自动变成可信拓扑。演示保留参考值，确认此阶段。

### ③ 选择方法、分解目标

目标 0.99、窗口 24h，允许损失为 `24 × (1 − 0.99) = 0.24` 等效小时。四类等权预算各 0.06h（3.6 分钟）：检测恢复、检查点回滚、容量亚健康、污染清零。

点击“保存预算并加入评估输入”，再人工确认阶段。预算保存不代替确认，也不证明组件达标。需要映射到 FIT、覆盖率、恢复时长等，再回代完整模型。

“选择子模型分配方法”支持 Availability、Equal、ARINC、AGREE 的适用性选择和比较。Availability 对应稳态可用度，其他方法对应适用任务可靠度；不能直接以子模型串联相乘宣称训练交付达标。见[数值方法](numerical-methods.md)。

### ④ 准备参数

先不勾选改进机制，形成基线。核对完整参数、单位、来源，逐项区分真实值与参考值。覆盖率和时长遵循界面标注。

使用资产先复制到任务、核对适用性与映射。修改绑定字段会解除旧绑定并保留本次值。确认阶段后开始正式计算。

### ⑤ 求解与权衡

点击“开始评估”。查看运行编号、正确交付均值、采样区间、P05/P50/P95、单窗口达标比例、损失账本、污染风险、预算差距及轨迹。

正式训练运行绑定当前任务、执行和完整已保存输入版本。计算完成仅进入待审核；核对结果后人工确认。前四阶段未确认时可独立试算，该运行不能后来冒充正式交付。

修改目标、参数、机制或版本会使旧流程过期。历史结果仍在，重新从目标确认并重算。子模型和比较结果不能替代正式训练评估。

### ⑥ 验证交付

检查输入摘要、模型版本、来源、固定资产、种子、误差和未验证项，下载报告，再“记录交付确认”。采纳或不采纳理由写入反馈。

置信区间只包含蒙特卡洛采样误差，不覆盖参数、传播、共因和结构误差。数学回归通过不等于真实产品达标。

## 4. 比较一个机制方案

保持规模、目标、窗口及采样一致，勾选一个机制，核对补丁。点击“比较基线与当前方案”，检查工具输入，再执行比较。入口以当前手工参数并清除机制勾选项为基线，不自动采用上一条历史运行。

查看配对收益与副作用。V4 独立工具的“应用到历史模型 V4”仅回写对应模型的候选，须回工作台核对、重新确认与正式评估。组合 Shapley 贡献不能直接以单项收益相加；有限搜索没有找到候选不等于工程不可行。

也可以复制基线任务，把另一方案的数据、会话和报告单独保存。

## 5. 真实文件与资产库

文件流程：**导入 → 检查/修正结构化提取 → 人工确认 → 核对映射和未映射字段 → 应用到设计/私有库 → 重新确认与评估**。

JSON/CSV/XLSX 有结构化读取；文本、PDF、图片的自动提取取决于单独配置的提取模型及能力。只切换右侧聊天模型不会配置文件提取。缺失项不补造，未映射字段不会自动进入模型，原参考值也可能仍保留。

“连接与配置”显示本任务 inputs 文件夹。把真实文件放到这里，变更形成新的待确认输入；归档任务不接收变更。旧全局 WATCH_ROOTS 已弃用，避免跨任务混入；变更不覆盖历史运行快照。

只读示例/公共库点击“复制到当前任务”，记录上游版本和摘要。私有草稿点击“校验并冻结版本”，修改用“复制为新版本”。核对口径、适用条件及模型映射后可“将已校验版本应用到训练”。

“提交公共库提案”仅生成候选。示例 illustrative 不等于产品验证。公共发布 HTTP 入口当前关闭，独立审核身份接入前不能发布；私有评估与候选提交正常可用。

## 6. 右侧 OpenCode 推进同一流程

原生官方输入框和设置管理模型、Base URL 与 API Key。任务配置登记了：

```text
Provider: zhipuai-coding-plan
Base URL: https://open.bigmodel.cn/api/coding/paas/v4
Model ID: glm-5.3
```

在本地官方提供商设置连接后再选模型。Key 不写入共享 Skill、任务包或报告。已验证本地 OpenCode 发现此登记模型、连接任务 MCP、打开模型菜单及 Base URL/API Key 设置入口；真实 GLM 账户鉴权、回答和工具调用仍待本机实际验收。

点击“同步当前设计”，只写任务名、ID、版本和摘要，不调用模型；完整设计通过 MCP design_get 获取。在官方输入框发送：

```text
/sd-dfr-remap 基于当前任务做万卡训练评估。
先读取 task_current、design_get、workflow_state，核对目标和参数来源。
逐阶段保存产物，执行到人工确认点，不代替我确认。
前四阶段确认后，用完整已保存输入正式求解，再建议一个机制对比。
保留示例标签，解释采样误差和未验证假设。
```

右侧澄清、读取资料、推荐方法、安排工具和解释；中间看结构化产物、核对与签认。两侧使用同一流程服务。

Agent workflow_save 后，领域事件使中间显示产物和“待人工确认”。在中间确认后让 Agent 继续读取状态。没有真实运行，聊天写“完成”也不会被当作计算结果。查看“本阶段过程产物”可展开任务书、参数、方法依据和运行编号。

取消保留产物；失败按当前输入重试。过期或已取消执行重新启动并确认，不声称从截断仿真续算。官方 UI 内部导航不会改变工作台绑定，用“返回关联会话”回到任务；失效连接可刷新恢复。

## 7. 导出与迁移

结果页可选择 HTML/Markdown，默认导出简洁正文和“验证与诊断摘要”；完整记录通过“下载结果 JSON”独立下载。勾选“包含完整技术附件”后下载离线 ZIP 包，同时包含两种正文、JSON 和校验清单。完整解压并保持同目录，附件可离线访问。失败运行独立提供诊断报告/JSON。详见[报告摘要与离线技术附件](2026-10-13-报告摘要与离线技术附件.md)。

任务包保留固化资产、已完成运行和历史摘要，不包含 OpenCode 配置、凭据、聊天会话。导入建立新任务，重新生成本机配置与主会话。软件包与任务数据包分别分享。

```powershell
pnpm task:export <taskId> <output.json>
pnpm task:import <input.json>
# 旧单工作区：先预检，再显式应用；原库和备份保留
pnpm task:migrate
pnpm task:migrate --apply
# 单个运行的复现
pnpm exec tsx scripts/export-run.ts <taskId> <runId>
pnpm exec tsx scripts/replay-run.ts artifacts/replay/<runId>
```

任务包包含真实输入、来源和结果，应按数据权限分享。详见[部署与移植](部署与迁移.md)。

## 8. 排查与边界

| 现象 | 操作 |
|---|---|
| Agent 未连接 | 启动本地服务，核对 .env 地址，刷新；手动求解仍可用 |
| 会话不清楚 | 对照任务条与具名主会话，点击返回关联会话 |
| Skill/MCP 未发现 | 创建主会话会安装；也可 bootstrap --task <taskId> 后 doctor --task <taskId> |
| 版本冲突 | 加载最新任务设计、核对变更，避免覆盖其他窗口 |
| 无法交付 | 按序确认前四阶段，再以当前完整设计完成正式训练 |
| 文件未进模型 | 检查人工确认、映射、未映射原因与参考值残留 |
| CTMC 不可用 | 配置本机 Python/SciPy，其他本地求解可继续 |
| 区间宽 | 按预定标准提高样本量并补实测证据，不挑选有利重跑 |

正式六阶段先覆盖 AI 训练集群；传统 RBD/FTA/BDD/CTMC 作为独立实验可用。AI 系统、NTN 等保留扩展入口，未完成产品语义验证。

报告前部列出实际启用措施与参数。默认六项为D-SDC、R-SDC、R-REPLAY、R-PROCESS、R-ELASTIC、C-FAST；“载入专家六项及参数”会显式恢复这些措施的专家目标参数和默认恢复链。常规CKPT、人工兜底已包含于基线，不重复领取收益。事件来源详情分别展示专家证据、审核备注、历史细分/FIT依据和本次校准说明；内网更新后保留参考说明作为历史证据，不能将其当成本次实测。
