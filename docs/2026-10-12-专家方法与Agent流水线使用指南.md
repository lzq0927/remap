# 专家方法、目标分配与 Agent 流水线

## 方法如何进入平台

原始来源是专家仓库的 `catalogs/review-2026-10-09/故障事件与可靠性机制收益审核.html`。平台归档来源输入、机制参数、原引擎和参考结果；运行时调用求解器计算，参考结果仅用于复现核对。

报告的方法依次是：事件发生率 `λᵢ=N×FITᵢ/10⁹` → 按事件适用范围执行检测和恢复回退 → 有限窗口离散事件仿真 → 单项与组合配对收益 → 枚举全部机制子集的 Shapley → 参数敏感性 → 时间账与事件账守恒复核。正确有效产出是窗口末保留的正确进度除以窗口；运行可用度单独计算。静默污染期合并，失败尝试耗时累加，基线已有保护不重复领取收益。

原报告的事件 FIT 拆分属于先验，不能当作产品目标向下分解。平台在候选措施计算前增加目标分配产物，不改写原故障率：

- **训练损失预算：** 总预算 `(1−目标)×窗口`，六项损失分别是停机、保存、回滚、期末污染、降速和局部容量损失。可选均分、按本次基线损失比例、手工权重。基线比例在各规模基线计算后冻结，再比较措施，报告可回看实际预算与缺口。
- **任务可靠度子模型：** 在“子模型目标分配”启用独立目标，可选 Equal、ARINC、AGREE，也可同步对比。Equal 均分故障率预算；ARINC 按基线率等比收缩；AGREE 使用复杂度、重要度和工作时间，按 `∏Rᵢ^Eᵢ` 检查合成目标。
- **运行可用度子模型：** 选择稳态运行可用度，使用 Availability 的串联对数预算，支持权重、固定目标和边界。独立串联前提须经架构确认。

子模型分配给出约束和设计缺口，不自动宣称子系统达标。其前向验证需要相应的 RBD/CTMC 等模型；整个训练方案仍用离散事件仿真验证有效产出。不能将训练产出目标当作无失效任务概率或稳态运行可用度。

## 操作演示

1. 启动 ReMAP，创建或打开一个任务，进入“可靠性设计与评估”。填写规模、窗口和各规模产品目标；不同代际/方案使用同一需求目标。
2. 导入或在任务目录放置真实输入。确认解析内容，更新事件 FIT、来源、机制覆盖率、恢复时间与回退条件。没有真实数据时保留先验/演示标记。
3. 在“预算与措施”选训练预算方式。若需要独立子模型分解，展开“子模型目标分配”，启用并明确独立指标、目标和参数，选择 AGREE 等方法。示例子系统参数仅用于演示。
4. 选择候选机制、物理恢复顺序和采样精度。默认专家复现采样计算量较大；第一次熟悉流程可主动选择快速探索，但不能把探索结果当成专家原始复现或正式达标证明。
5. 在右侧本地 OpenCode 点击“加载 Skill 并选择执行方式”，或在原生输入框发送 `/sd-dfr-remap`。Agent 读取同一任务的已保存设计，说明推荐理由，并通过原生 question 工具显示可点击的“全自动设计与评估 / 辅助设计与评估”及各自解释。需要先在 OpenCode 官方设置中连接模型；选择卡由实际 Agent 调用问题工具后出现。
6. 选择全自动：Agent 调用 MCP `workflow_automatic`。中间六阶段自动滚到当前步骤，前四步各保留约两秒阅读时间，显示说明和已冻结的过程产物；求解耗时取决于真实采样量。计算结束后也留出阅读时间再展示报告。点“步骤说明与记录”可查看详细内容。前五阶段显示“自动完成 · 待总审”，最终报告“待人工确认”。阅读停留不改变采样精度，不伪造计算耗时或人工确认。
7. 选择辅助：Agent 根据本次输入判断下一步，例如补充资料、指标分解、措施选型或结果解释，复用已确认信息；每阶段保存产物，您在中间工作台确认后继续。自由输入并不等于授权自动执行；已有执行则接着处理，不重复启动。右侧和中间共用流程状态，不是两份评估。
8. 完成后查看报告中的目标分配、基线/单项/组合、逐事件损失、Shapley、敏感性和复核项，导出 HTML/Markdown/JSON。核对适用前提后点击“记录交付确认”。公共资产仍需独立审核发布。

执行中可取消。修改分析输入会使旧流程失效并停止旧计算；结果保留在历史记录。重新执行必须使用新的输入版本，不得用旧结果确认新目标。重复启动会返回冲突，避免同一任务产生两套同时运行的流水线。

加载 Skill 采用后台派发，启动请求立即返回，提问和长时间求解继续在原生 OpenCode 中显示，不让工作台按钮一直等待模型完成。同一会话的重复派发会被拒绝；启动失败会显示诊断。打开右侧面板时会准备最新任务 Skill，已有会话也能使用更新后的命令。

## 解耦与内网适配

右侧仍是本地安装的官方 OpenCode。打开任务时平台按需启动该任务的回环服务，以 `OPENCODE_DB=<任务目录>/.opencode-runtime/opencode.db` 隔离会话，并单独存放运行状态；端口按任务保留，让原生浏览器偏好也分开。旧版本仅过滤工作台下拉框，共享原生服务仍会显示其他项目；现在隔离的是原生会话数据库，不删除其他项目记录。迁移只导入任务绑定的历史会话，目录不匹配则拒绝，原始会话保留。迁移失败会阻止继续关联并明确报错。

部署机器需要安装支持 `OPENCODE_DB` 的原生 OpenCode（已验证 1.18.35），可用 `OPENCODE_BIN` 指向可执行文件。启动时会验证数据库路径；不支持隔离的版本会提示升级，不回退到共享数据库。本机已有 OpenCode 提供商配置与凭据继续使用，不复制密钥进任务。平台关闭时结束它启动的任务服务；独立运行的 4096 服务不受影响。任务配置、运行数据库和临时迁移文件不进入 Git 或任务导出包。其他 Agent 仍通过可替换 AgentIntegration 接口与标准 MCP 接入。

分配模块在 `packages/allocation` 与 `packages/analysis/src/audit-allocation.ts`；流水线服务在 `apps/api/src/automatic-workflow.ts`；标准 MCP 注册独立于 OpenCode；Skill 在 `skills/sd-dfr-remap`。其他 Agent 可使用同一个 Skill 与任务绑定 MCP。

已有任务打开关联会话时会准备任务配置；点击加载 Skill 会再次安装最新 Skill 与 MCP 配置。内网部署沿用已有内网部署指导，真实输入、私有资产、Agent 配置和密钥只保存在本地任务目录及本地配置中。

本次自动编排仅支持当前专家训练审核口径；其他产品、历史 V4 与复杂传播场景由交互模式选择现有工具继续分析。误报开销、共因故障、训练收敛及实际 DP 性能等原报告未建模边界仍需补充模型，不能因自动报告生成而视为已验证。
