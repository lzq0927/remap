# 可靠性设计与评估：分轮评估与Agent协作

更新：2026-10-15。平台围绕“目标是什么、现状差在哪里、改善什么、改善后如何、哪些依据仍需验证”组织工作。默认按专家口径计算可用度，保留完整六阶段确认和可追溯的每次试验。

## 从现状到改进

| 环节 | 用户看到什么 | 下一步 |
| --- | --- | --- |
| 可用度目标 | 当前模型的主规模目标、其他规模目标与窗口 | 核对需求 |
| 故障模式 | 按对象与hard/slow/sdc分类的FIT、占比与来源 | 核对现状证据 |
| 可用度分配 | 第一轮固定现状，不预先改造分配 | 确认评估策略 |
| 可靠性措施 | 当前选择的措施及能力；按实际数量、类别和部署状态说明 | 核对措施与适用条件 |
| 计算与权衡 | 第一轮独立结果、损失与贡献 | 可生成分配、手动改参、再评估 |
| 验证与交付 | 每轮及对比报告、证据、区间、未满足项 | 人工记录交付与采纳理由 |

第一轮结束后先看本轮结论。点击“生成AGREE改进分配”只生成建议；可选择规划规模，查看重要度、分配责任、要求值、依据和规划试算。点击“载入AGREE分配建议”或自行编辑后，再点“评估本次改进方案”才会运行独立改进轮。

“新建参数方案”提供调整对象和参数选择，可填写任意支持的能力要求；单参数对照只更改该字段，其余参数沿用现状。若在上次改进上继续调参，先恢复/读取该方案，再改明确字段。每次参数和结果独立保存；可以反复评估、单独导出，或选择多次结果生成比较报告。比较包含各规模曲线、参数差异、各轮结论与贡献排名。生成建议不等于完成第二轮。

改变正式草稿后只复核受影响阶段及后续，目标/规模/口径变化才从第一步开始。独立改进实验不会改写第一轮或使其确认过期。旧V4放在高级设置的历史模型中；历史结果保留原口径，不和当前指标混比。

## AI训练集群样例默认值与方法

| 规模 | 目标（约） | 中断MTBF |
| --- | ---: | ---: |
| 50万卡 | 98.5% | 0.6h |
| 20万卡 | 99.39455% | 1.5h |
| 10万卡 | 99.69636% | 3h |
| 万卡 | 99.96955% | 30h |

目标以50万卡锚点经 A=MTBF/(MTBF+参考恢复时间)推导。实际可用度依故障FIT及检测/恢复/检查点等措施计算，不能把目标推导参考时间当作统一实际MTTR。1000卡仅为参考曲线点。旧任务保留已保存目标，升级不覆盖编辑值。

第一轮正Shapley形成重要度起点，AGREE分配工程责任及允许损失，再通过机制组合仿真反推参数要求。工程责任不是各机制独立的物理损失路径；检查总可用度目标，不强迫每条路径都满足独立上限，也不合并各规模最严要求。专家机制库提供作用范围、阶段、参数参考及成本；不足时给出明确标识的工程要求，交产品专家讨论。自动规划不降低FIT；用户提供FIT改造时保留逐事件来源。

第一轮Shapley相对原基线，改进轮Shapley相对第一轮，分别解读。均值达到目标且95%区间跨过时标为待复核。规划试算、代码测试通过、模型评估与产品实测分别记录；其他规模未达标须明确展示。

## 右侧Agent如何协作

同步当前设计后用自然语言或`/sd-dfr-remap`说明当前问题。例如：

- “评估当前选择的措施与参数，先给我现状报告。”
- “依据现状Shapley，按当前主规模与目标生成AGREE分配，先给我看建议。”
- “只修改我指定的一个能力参数，其他值沿用现状，评估并导出。”
- “载入刚才的分配建议，按我提供的参数要求调整后再评估。”
- “比较这三次评估，各规模分别给结论和措施排名，导出报告。”

Agent读取已保存输入和历史快照。明确要求直接执行对应步骤；意图缺少时才简短澄清。明确全自动运行只到第一轮报告待审核，不自动开展后续改进；阶段签认、输入确认与交付仍在工作台操作。

| 工具 | 用途 |
| --- | --- |
| task_current / design_get / workflow_state | 当前任务、指标、完整输入与流程状态 |
| run_list / run_status | 查找各轮ID、读取完整冻结快照 |
| analysis_solve / workflow_automatic | 正式或独立第一轮；自动模式须有用户明确要求 |
| audit_plan | 根据第一轮生成AGREE分配，不执行改进轮 |
| audit_evaluate | 执行一次明确的改进方案，可关联计划ID |
| audit_compare / report_export | 同源多次结果比较、各轮/比较报告及离线包 |

项目Skill源在`skills/sd-dfr-remap`。任务连接准备时递归同步最新Skill及参考文件，内容有变化时刷新该任务原生实例；普通重连不重复刷新。开发启动、Agent启动和bootstrap也会自动同步根目录本地发现副本；`pnpm skill:install`可单独更新。拉取升级后重启API并在右侧重新连接/准备任务，可同步到已有任务。其它Agent安装同一Skill并连接绑定任务的MCP 0.3即可使用领域服务，无需仿制聊天界面。

## 证据与更通用的设计

故障模式按对象和类型组织，显示FIT及来源。总占比按全部故障合计1；类内占比按hard/slow/sdc各自合计1。保留参数基准、单位和证据等级，更新一类数据不擅自重造其它类。

新可靠性机制库覆盖发生前/发生时/发生后/恢复失败，分别说明提高MTBF、缩短MTTR、减少保存/回滚/污染及新增开销。精度专用检测不能外推全体故障。缺少适用比例、成功率或成本时标为工程情景，不能默认为产品保证。

系统建模可保存架构、部署、来源、性质与RBD/FTA/CTMC等分析案例。各辅助方法保留自己的指标语义；其他产品需各自的数据、传播模型和校准。导入材料、提出草案、真实执行和专家验证分别有记录；适配器未配置或缺真实证据时不宣称已完成验证。
