01

链路透明恢复

R-LINK-LOCAL · 新增
−340.5s常规单次等效损失

NVLink 分层方案延伸 · 拟议流程；跨平台目标待验证

工作原理 · 缩短瞬态故障停顿；成功时避免 CKPT 回滚

在通信数据尚有可信重放副本时，先在链路附近纠正或重试，再升级到应用恢复。FEC 处理可纠正误码，重传处理未纠正的数据，物理重训练处理短暂失链。模型只给“现有保护仍未覆盖、但新增能力可挽救”的事件记增量收益。

何时触发

信号／启动条件

不可纠正误码、重试告警或 Link Down；故障已进入新增保护路径。

必须满足的门槛

重放缓冲仍有效、序号和确认状态可核对，未发生不可逆的错误提交；重试次数与超时上限须配置。

执行时机

链路异常出现后立即由硬件/驱动执行，尽量早于应用超时。2s 是完整训练可见停顿预算，不是单次物理重传耗时。

执行主体

链路固件／驱动；训练监控记录停顿。

执行流程

  1. 暂停受影响通道的新事务，记录序号和最近有效确认点。
  2. 依照错误等级纠正、重传或重训练；校验重放数据并抑制重复提交。
  3. 确认链路稳定与事务完成后恢复投递；达到重试上限则明确向上层报错。

成功判据

所有待处理事务完成且数据校验通过，训练继续产生正确 step；不能仅凭 Link Up 判断成功。

不适用／禁止直接续跑的情况

永久物理损坏、重放数据丢失、状态已污染或需要重复无限重试时，不走透明续跑。

常规损失 = 12.5 + 180 + 150 = 342.5s；成功损失 = 2 + 0 = 2s。

适用范围

工作原理 · 缩短进程初始化阶段

FP8 计算路径 SDC 检测

D-SDC-FP8 · 用户方案 · 检测扩展
+95 个百分点适用 SDC 子集的登记检出率

用户补充方案 · 拟议流程；性能与覆盖率为验收目标

工作原理 · 提高特定精度路径检出率，减少长期污染窗口

将当前只对 BF16 验证的检测链扩展到 FP8 实际执行路径。可选择独立校验、差异重算或经验证的硬件检查实现；登记的 95% 是能力目标，不预设实现。正常量化误差、舍入差异与硬件 SDC 需要分别判定。

何时触发

信号／启动条件

每个受保护 FP8 算子或 step 边界主动执行检查；校验残差越阈、scale 非法或独立计算不一致触发恢复。

必须满足的门槛

阈值经无故障训练标定；检查输入与元数据有可信锚点；异常结果尚未成为已提交优化器状态。

执行时机

算子输出提交前或最迟当前 step 提交前；若抽样跨多个 step 检查，须另算延迟和污染窗口。

执行主体

低精度算子库＋SDC 检测服务＋step 提交控制器。

执行流程

  1. 登记实际 dtype、scale、算子与阶段，按互斥风险子类挂接，不能只读取模型权重文件格式。
  2. 对算子结果和元数据执行已验证校验，暂缓异常结果提交。
  3. 用可信 step 输入、RNG 和旧参数在健康资源重算，确认结果后只提交一次。
  4. 重复异常则隔离资源并升级 CKPT 恢复；未检出的错误仍保留原长期漏检分支。

成功判据

目标子集 SDC 的检出率达到 95%，误报和性能开销可接受；已检出事件从可信状态重算后不污染参数。

不适用／禁止直接续跑的情况

普通量化舍入偏差不直接判为硬件故障；没有可信 step 起点、已经跨 step 污染时，不承诺只损失一个 step。

在适用子集内：登记覆盖 0% → 95%，残余漏检 100% → 5%。q 为该路径的 SDC 风险占比；后续核心检出率按 Σ(q_j×c_j) 加权。

适用范围

使用 FP8 的算子计算及其量化元数据，覆盖前向与反向需要分别验收。不是全部 AI Core SDC。

证据与假设

95% 是用户提出的验收目标；0% 是尚未验证能力的保守记账，不是断言原检测器真实无效。低精度计算是混合精度执行，FP4 存储不能直接证明 FP4 训练计算占比。

成立前提

校验覆盖实际算子、输入／输出格式、scale、累加精度与提交边界；可从可信 step 起点重放，保留 RNG 和数据游标。

失败后的处理

检出但无法在 step 内恢复则回到干净 CKPT；真正漏检进入原约 5 天后的发现与回滚路径，保留错误之前的进度。

成本与限制

校验计算、访存和误报引发的重算开销未知，不能假定免费。若采用 ABFT 实现本检测，则同一校验不另计两份覆盖。

与已有机制的重叠

BF16／FP8／FP4 按互斥的首个错误来源分配风险；W4A8 等混合算子不能同时把同一错误计入 FP4 和 FP8。检测率与故障发生 FIT 是不同参数。

验收指标

针对每种精度的前向、输入梯度、权重梯度及 scale 做分层注入，分别报告真 SDC 的检出率、误报率、发现时延和重放成功率。

需记录的观测指标

按 dtype／FWD／DGRAD／WGRAD 的 SDC 覆盖率；scale 与累加路径覆盖；误报率；检测到提交的时序；校验开销与重算成功率

算子 ABFT／实时矩阵校验

D-ABFT · 用户方案 · 漏检补充
+4.5 个百分点同一适用子集的两级联合检出率

用户补充方案 · 拟议流程；性能与覆盖率为验收目标

工作原理 · 捕获已有检测的剩余漏检；以正常态开销换取更高覆盖

对 C=A×B，可比较 C×r 与 A×(B×r) 的校验残差，避免完全重复一次矩阵乘。必须使用实际量化后的运算定义并校准容差；可信检查路径是关键。数据在生成校验值之前已被一致污染，或错误位于校验盲区时，仍可能漏检。

何时触发

信号／启动条件

受保护算子每次执行时计算校验；残差超过按形状、精度和数值范围标定的阈值则报错。

必须满足的门槛

校验元数据与检查路径可信，校验结束早于参数提交；抽样策略的漏检必须纳入覆盖率。

执行时机

与算子尾部融合或紧接算子执行，异常 step 不提交。

执行主体

算子实现／编译器＋训练正确性守护器。

执行流程

  1. 保留可信输入标识并生成校验向量，计算应满足的代数关系。
  2. 完成算子后用适当精度计算残差，与无故障分布校准的阈值比较。
  3. 异常时冻结本 step，换可信资源重算；一致性通过后单次提交。
  4. 记录与主检测器的交集、补漏集和共同漏检集，更新条件检出率。

成功判据

在主检测器实际漏检样本上达到约定补漏率，且正确性验证、误报和 0.1% 性能预算均通过。

不适用／禁止直接续跑的情况

不把固定浮点精确相等当作通用判据；不将传输 checksum 等同于算子 ABFT，也不默认检查器不会出错。

c_total=c₁+(1−c₁)c₂|miss；95%+5%×90%=99.5%。每 1000s 正常运行的吞吐损失预算相当于 1s 满速产出。

适用范围

有可验证代数关系的 GEMM／相关线性算子；不自动覆盖非线性、控制流和所有输入错误。

证据与假设

0.1% 来自用户预算，条件补漏率 90% 为待验证示例，并非已有实测。99.5% 只适用于第一道已有 95% 有效覆盖的同一算子子集；尚未验证的低精度路径不能直接套用。此公式不要求两道检测独立。

成立前提

校验向量／校验值可信、正确考虑量化与浮点误差；若用于补漏，必须在第一道漏检样本上测条件检出率。

失败后的处理

检查不通过则阻止提交并用可信输入重算；一致性无法恢复则回滚干净 CKPT。ABFT 漏检仍走约 5 天发现路径。

成本与限制

0.1% 为目标而非保证；小 batch MoE、频繁访存、同步与高精度校验可能显著增加开销。误报率和错误重算成本须另测。

与已有机制的重叠

若 ABFT 本身用于实现 FP8/FP4 的 95% 检测，两者是同一条能力，不能再按 95%＋补漏计收益。只有独立新增、在剩余漏检上验证的检查才算补充。

验收指标

按算子形状和 dtype 采集故障注入矩阵；测联合漏检、误报、每 step 实际吞吐和检测提交边界。

需记录的观测指标

条件补漏率而非单独检出率；两级共同漏检；无故障误报率；按形状的实际开销；可信重算成功率

工作原理 · 缩短局部恢复的通信重建阶段

仿照 NCCL shrink 的思路，让健康成员对故障 rank 达成一致，终止挂起通信并构造新通信域，尽量复用可验证的拓扑信息。通信库恢复连通只完成一部分；框架还必须修复训练状态和并行关系。

何时触发

信号／启动条件

通信异步错误、集合操作超时或 rank 心跳异常，经确认有成员不可继续。

必须满足的门槛

故障成员可被一致隔离，目标版本提供经过验证的恢复能力；框架可在新成员集合上保持正确训练。

执行时机

检测和故障分类之后，局部恢复路径的通信阶段；不改变原检测时间。

执行主体

HCCL 运行时＋弹性训练控制器。

执行流程

  1. 冻结当前 epoch 的提交，各存活成员一致确认待排除／替换 rank。
  2. 有界中止挂起通信，隔离旧通信域，创建新通信域并更新成员映射。
  3. 恢复必要分片与 batch／梯度规则，更新与通信绑定的图或算子状态。
  4. 通过集体验证和一个正确 step 后提交新 epoch；失败则升级恢复。

成功判据

所有存活成员在同一 epoch 上无死锁运行，正确训练语义保持，通信阶段达到 10–20s 目标。

不适用／禁止直接续跑的情况

仅调用普通子通信域拆分，不代表能从挂死父通信域恢复；剩余成员无法构成模型时不能直接缩容。

单次适用局部恢复少 45s；若确实只有 1/50 域损失产出，该阶段少损失 45/50=0.9 个全系统等效秒。

适用范围

故障 rank 可移除或替换，训练状态和并行语义支持继续；HCCL 目标实现需逐版本验证。

证据与假设

NCCL shrink 提供可参考的恢复设计。HCCL 9.0 文档中的部分暂停／恢复接口为保留接口，不能据此声称当前 HCCL 已具备等价 shrink；15s 是待实现和测试的工程目标。

成立前提

统一故障成员列表和通信 epoch，残余 rank 无死锁；权重、优化器分片、全局 batch 与梯度归约语义已处理。

失败后的处理

移除失败、成员分歧或状态无法恢复时中止局部尝试，进入适用的自动全局恢复；少数卡死／根因不明进入人工兜底。

成本与限制

成员协调、重分片和再次故障处理都需计时；本项并不自动消除状态重载或模型重分片时间。

与已有机制的重叠

验收指标

CANN 的流捕获 API 支持将任务保存为运行实例以减少主机投递开销；该能力本身不保证跨进程持久化或故障后免初始化。7.5s 是图缓存／预热方案的候选目标。

成立前提

缓存与模型、shape、dtype、算子版本、设备、地址和通信域兼容；不兼容时重新捕获并验证。

失败后的处理

命中失败或图验证失败则完整编译／捕获；记录失败尝试和校验额外耗时，不复用旧通信句柄。

成本与限制

缓存生成、存储、预热内存与失效维护成本待测；本表不同时计稳态 host launch 加速收益。

与已有机制的重叠

与预热进程／运行时快照共享 60s 启动预算，其中图准备只有 30s；先确认剩余工作再计增量，不能叠加 40s、45s 和 22.5s。

验收指标

按固定／动态 shape、不同并行拓扑及软件升级测试缓存命中率、图准备关键路径和恢复后正确性。

需记录的观测指标

图准备耗时；缓存命中／失效原因；首个正确 step 时间；缓存与预热资源成本；失败回退额外耗时

后续接入总体模型的规则

① 当前事件 FIT 是已有保护后的残余率。原始库的 96.6% / 2% / 1.4% 预算保持不变；新增压测机制若降低 SDC 发生率，应在情景中对适用子集乘 0.75，改善后的比例不强制归一回原值，否则会抵消预防收益。

② 对适用事件，若使用完整单事件损失口径：E[L′]=q×L_success+(1−q)×(T_failure_extra+L_fallback)。q 为条件成功率；失败额外耗时只计超出对照路径的部分，避免重复计检测。

③ 对父事件，仍需适用比例 a：E[L_parent′]=(1−a)×L_base+a×E[L′]。启动/读取阶段改善必须嵌入完整恢复路径，不能直接把阶段时间当整次事件损失。

④ 隔离与弹性、预热与快照、异步与旧 C-FAST 均有重叠。组合评估时按同一事件的分支与恢复阶段记账，不相加本表减少量。正常运行开销、资源代价和失败尝试不能默认为零。

⑤ 多级 SDC 检测按条件补漏计：c_total=c₁+(1−c₁)c₂|miss。按实际路径处理共有漏检，不能默认独立。检出率不是恢复成功率；发生率下降也不等于检出率提高。网络保护不能直接替代算子正确性验证，静默污染不会因快速接替自动清除。

⑥ 每次触发至少记录：事件 ID、根因与影响域、dtype／算子、触发证据、机制 ID、前后状态版本、检测／开始／校验通过时刻、恢复分支、成功与失败原因、回退位置，以及正常态开销。用同一事件 ID 合并多个告警，避免重复统计。
