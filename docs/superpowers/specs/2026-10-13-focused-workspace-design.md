# ReMAP 聚焦工作台设计

用户已要求完成现状分析、业界调研和计划后继续实施。本轮按此顺序执行，采用任务导向的渐进展示；依据见 `docs/2026-10-13-前端现状分析与业界调研.md`。

## 信息架构

左侧维持六个真实功能入口，分为设计、资源、交付与连接；产品场景保持可用性标注。中间上方显示任务、产品/模型和当前运行，页面标题只承担当前模块定位。目标、规模、窗口与配置状态显示为简洁上下文；历史结果仍明确冻结口径。

六阶段导航固定在中间工作区，默认“按步骤”显示当前步骤的输入/产物：0目标与口径、1故障与证据、2预算与措施、3参数核对、4计算与权衡、5验证与交付。提供“全部配置”入口，便于专家批量编辑。视图切换保持 AuditWorkbench 挂载与编辑状态，不改设计输入修订、不自动确认。自动流程推进时切回步骤视图并跟随真实执行步骤。

第4阶段可独立试算；是否属于正式流程继续由既有前序确认与输入版本规则决定。第5阶段优先显示结果与下载/复核摘要，无结果时提供“前往计算”。切换阶段保留输入和旧结果；过期提示保留，不混淆输入与冻结运行。

## 结果组织

专家结果采用“结论概览、方案收益、贡献分摊、风险与敏感性、全部分析”视图。概览呈现当前规模判断、正确有效产出、区间、目标缺口和建议；收益与贡献的区别、负值和区间解释继续保留。所有视图共享同一冻结结果与当前选择规模，不重新求解、不重排旧条件分析。图和表的数值来源不变；全部分析用于集中复核。

通用工具结果保留专用视图。失败独立诊断；简短验证摘要、独立 JSON 和可选离线 ZIP 保留前序已验收行为。视图选项是 UI 状态，历史任务无该偏好时按新默认显示，不迁移或修改数据。

## Agent 与资源

继续嵌入本地原生 OpenCode。外围展示真实任务名称、当前步骤和输入修订；修正专家场景所有步骤都传 `step=audit` 的上下文问题，提供真实 workflow step ID，同时单独声明 assessment。同步接口从任务保存的设计生成真实阶段、修订与运行关联，客户端当前模块仅接受预定义名称。主要动作为“加载 Skill 并选择执行方式”，会话创建、同步、复制、设置等管理操作置于可展开区，原生 iframe 保持挂载以保留对话。放大、关闭、独立打开仍可使用；模型/API 配置仍由官方 UI 管理。

任务主页增加名称搜索与匹配计数，不改变归档、恢复、复制、导入/导出和命名行为。资源页使用统一的标题、按钮、表单与表格节奏；不新增虚假的覆盖率、风险或智能建议。

## 视觉与适配

采用浅色工程工作台：暖灰背景、白色工作区、浅色导航与石墨文字、低饱和青绿强调；红色用于错误/负向语义。中文正文14–15px，数字使用等宽数字；主要操作明显，辅助文案降低层级，必要告警不隐藏。使用本机字体，不依赖外网字体/CDN。

桌面为导航＋工程区＋可收起原生 Agent；中等宽度提供更大工程区与底部 Agent；手机单列导航/内容，阶段栏可横向滚动，表格局部滚动。支持键盘切换视图、焦点可见和减少动态效果。固定流程栏不得遮挡当前内容。

## 模块与边界

布局与视图组件放在 `apps/web/src`，共享数据口径继续位于 contracts/reports。App 保留设计、任务、执行事件和 API 状态；纯展示组件不访问数值引擎。新增样式限定作用域；无后端数据 schema 变更、无新增 UI 第三方运行依赖。现有实验导出、Skill/MCP、任务资产和人工确认权限不变化。

验收覆盖：全新/历史任务、六步切换、全部配置编辑保留、自动跟随、失效输入提示、多个规模、收益/贡献视图、负值、未启用 Shapley、失败诊断、资源页、原生 OpenCode、本地上下文、桌面/手机布局和离线报告附件。
