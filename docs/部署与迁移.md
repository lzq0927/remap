# 部署与迁移

公司内网请使用 [内网开发指南](内网开发指南.md) 的内网配置与离线安装流程；本页的通用在线安装示例适用于开发环境。

## 软件与数据分别交付

软件包由 `pnpm build` 和 `pnpm export:release` 生成。清单列出每个相对路径、长度和 SHA-256；不包含开发机依赖、Python target 目录、任务数据库、凭据或本机 `.env`。解压后安装 Node.js 24+/pnpm 11，执行 `pnpm install --frozen-lockfile`、`pnpm bootstrap`、`pnpm run doctor`、`pnpm start`。bootstrap 只在缺少时生成模板和本地 Skill，不覆盖现有配置。

从任意目录执行 `node "<解压目录>/scripts/launch.mjs" start`。配置中的相对 DATA_DIR 从软件根解析；改变 PORT 时同时设置 RELIABILITY_API_URL。开发端口通过 WEB_PORT 配置。目录可以包含空格和中文。

任务通过主页或 CLI 导出 JSON 包。包携带 schema 和内容摘要，服务导入前校验 schema、行值与摘要；不解压任意文件路径。相同名称会创建新任务，不覆盖源任务。历史运行保持原内容和摘要，当前设计绑定目标任务；旧会话与过程身份需要在本机重新关联。任务包可能包含用户输入和来源数据，不能当作通用软件包公开。

## 任务 CLI

API 启动后运行：

```powershell
pnpm task:export <taskId> <输出.json>
pnpm task:import <输入.json> "新名称"
pnpm task:migrate --dry-run
pnpm task:migrate --apply
```

导出默认不覆盖已有文件。CLI 只连接本地回环 API，不输出 Agent 凭据。旧工作区迁移使用单独 API 入口，默认预检；实际迁移前应停止仍写入旧数据库的服务。服务验证源文件稳定、生成一致性快照与备份，保存迁移清单后注册历史任务。未完成运行不能保证自动续算。保留原目录和备份，恢复需依据清单核对，禁止用新数据直接覆盖旧目录。

## 可选依赖与诊断

OpenCode 可由本机路径、项目依赖或 PATH 发现。服务健康检测使用官方 global/health，版本检查与模型能力验证分开记录。原生模型及 provider 权威在官方 UI；不把有效连接等同于真实 GLM 对话或工具调用通过。

CTMC 需要 Python、NumPy 和 SciPy；其他求解器无需 Python。设置 PYTHON_EXECUTABLE 或 RELIABILITY_PYTHON 指向本机解释器，或使用 PATH 的 python/python3、Windows py -3。doctor 检查实际导入；设置 RELIABILITY_REQUIRE_CTMC=1 可使缺少 CTMC 依赖成为必需检查失败。

`pnpm bootstrap --task <taskId>` 在 API 已运行时生成本机任务 MCP 配置，不创建会话或请求模型。`pnpm run doctor --task <taskId>` 额外验证真实 MCP initialize/listTools/task_current，API 必须已运行且 DATA_DIR 指向同一任务注册表。检查只读取任务，不调用模型。无 task 参数时诊断本机软件、可写目录、OpenCode、Python 和最小数值求解。

## MCP 与不同 Agent

连接现有 API 的 MCP 代理需要已部署的评估服务、注册任务及任务范围授权；仅代理不能宣称是独立数值引擎。任务工作区由服务生成绑定当前任务的 MCP 配置。

软件源包包含领域服务和数值引擎，可在安装依赖后启动本机 API，再把任务 MCP 接入支持标准 MCP 的 Agent。独立 runtime 包及 Skill 安装方法以其 manifest/README 为准。工具发现通过不等同于另一 Agent 已正确安装 Skill 或完整工作流已验收。

## 验证范围

`pnpm verify:portable` 检查软件清单和敏感路径排除，在本机新目录安装依赖后执行任意 cwd 启动、中文/空格路径、变更端口/数据目录、本地最小求解和任务导出/导入检查。验收 JSON 记录实际模式和结果。

在第二台物理电脑的冷安装、另一种 Agent 的 Skill 与工具端到端验收、GLM 真实调用仍需单独记录。没有这些证据时不宣称跨机或跨 Agent 已验收。公共发布当前不可用，候选提交可用。
