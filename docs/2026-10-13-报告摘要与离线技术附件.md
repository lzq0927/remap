# 报告摘要与离线技术附件

工作台和 HTML/Markdown 正文使用同一份冻结运行的“验证与诊断摘要”：检查结论和数量、异常/提醒、模型与来源版本、指标、输入摘要、输入哈希及文件/资产版本追溯。最多展示六条异常/提醒，长说明在正文截短；完整内容始终保留在 JSON 和运行数据库中。没有专门检查记录的历史运行明确提示“计算完成不等于验证通过”；未执行检查不会显示为通过。模型内守恒通过不代表产品实测认证。

## 工作台下载

1. 打开任务中的评估结果，或在“实验与报告”中选择历史运行。
2. 选择 HTML 或 Markdown，点击“下载报告”：默认正文不附带原始 JSON 代码块，也不在隐藏区域嵌入完整输入/结果。
3. 点击“下载结果 JSON”独立下载完整运行记录。成功附件名为 `reliability-<runId>.results.json`；失败或取消的附件名为 `reliability-<runId>.diagnostics.json`。失败界面只显示失败诊断，不展示残留成功结果或方案建议。
4. 勾选“包含完整技术附件”，点击“下载离线报告包”。ZIP 包同时包含 HTML、Markdown、完整 JSON、`manifest.json` 和 `README.txt`。完整解压后保持文件同目录，正文的相对 JSON 链接无需平台服务或网络即可访问；浏览器可能直接打开本地 JSON，也可在文件管理器读取。

只下载单个 HTML/Markdown 时，需要另行下载 JSON 并保持附件原文件名、放在正文同目录。正文也提供在线 JSON 链接，在线链接依赖原平台与任务访问权限；它不替代离线附件。不要只拷贝报告包中的正文文件而遗漏 JSON。

## 保存与复核

完整 JSON 与原有 `format=json` 使用相同运行结构，包含完整输入、固化资产/文件快照、未舍入结果、诊断、样本及运行事件（以原运行实际记录为准，不补造历史缺失数据）。流水线审核上下文按导出时的实际确认状态附加。正文变短只调整渲染，不裁剪数据库、运行记录、任务包或复核资产。

`manifest.json` 的 `schemaVersion=remap.report-package.v1`，记录任务、运行、输入哈希和各导出文件的 UTF-8 字节数、SHA-256。清单不对自身计算哈希。文件哈希用于检查传输完整性，不是数字签名或真实性认证。任务完整迁移仍使用任务包导出/导入；报告包是某次运行的阅读与复核附件，不替代整个任务的文件库。

专家复现脚本仍保存原始 `result.json` 与 `verification.json`，并输出完整离线报告包及同目录 JSON，不依赖在线附件。

## API 与 Agent

所有导出使用任务隔离端点 `/api/tasks/<taskId>/runs/<runId>/report`：

| 查询 | 返回 |
|---|---|
| `format=html` / `format=md` | 简洁正文和附件链接 |
| `format=json` | 完整运行 JSON，不改变原有 JSON 结构 |
| `format=zip` | 离线报告包 |
| `format=html&includeTechnical=true`（或 md） | 同一离线报告 ZIP 包 |
| `format=manifest` | 正文、JSON 和离线包的下载描述，不返回 ZIP 二进制 |

MCP 的 `report_export({id: runId, query: {format: "manifest"}})` 返回可下载文件描述；传 `format=zip` 或 `includeTechnical=true` 也返回该描述，避免把压缩字节当文本塞进 Agent 对话。既有 md/html/json 工具调用保持兼容。下载地址不包含任务令牌；鉴权仍由任务范围和当前部署访问控制执行。

本次未调整求解算法、贡献排序数值或采样设置。自动化验证覆盖默认正文无原始 JSON、成功/失败分离、历史检查缺失、任务隔离、原始数据不变、附件完整性及桌面/手机解压后的本地离线访问。
