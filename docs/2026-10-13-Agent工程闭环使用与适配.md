# Agent 辅助工程建模闭环

2026-10-14 更新：内置形式化运行时已移除，AI 集群主流程见 [六阶段样例验收](AI集群样例验收.md)。本工程建模模块按[新版主设计稿](superpowers/specs/2026-10-13-agent-assisted-engineering-design.md)实现第一条 AI 集群工程闭环。系统设计、可靠性分析方法、求解工具和运行证据分别保存，通过稳定 ID 和版本建立联系。

## 在本地操作

1. 打开任务的「系统建模」。可以创建空白设计、创建 AI 集群合成示例、导入工程 JSON，或者复用任务资产。
2. 在「材料与 Agent」导入 PPTX、Markdown、TXT 或 JSON。保留文件 SHA-256、原始字节、文本及页/段落/图元定位。关联到当前模型后点击「保存模型」。PPTX 导入提取图中文字、连接端点和备注，不承诺自动识别所有绘图语义；PDF/图片仍通过已有「输入与来源」入口处理。
3. 输入需要讨论的建模问题，交给原生 OpenCode。Agent 使用当前任务 MCP 读取资料并提交工程草案。「草案审阅」显示当前/候选差异及基线修订；用户接受才产生新版本。并发修改导致基线过期时重新提案，不覆盖草稿。
4. 在「系统设计」编辑架构、部署、功能关系和时序。画布支持拖动、连接、对象属性、位置数字编辑、自动排版、多个视图、撤销/重做和 SVG/PNG 导出。故障来源、功能影响和搜索只改变显示；分析维度需要在具体案例中配置。
5. 在「分析与验证」编辑独立的 RBD 成功逻辑、FTA 失效逻辑，或管理员配置的 P/外部工具输入。填写问题、假设、适用范围、机制及性质。保存后校验并运行。
6. 「运行证据」保留工具/版本、原始输出、输入快照、摘要、适用范围及反例。外部工具的符号绑定可定位系统对象；查看旧快照或重放不会替换当前设计。语义变化后旧证据显示提示，调整布局或记录决策不使计算证据过期。
7. 在「决策与复用」记录选择、备选代价、依据、重审条件和运行引用；保存为任务私有草稿资产。上方「复用任务资产」从冻结包创建新模型。导入证据明确标记来源，不冒充新运行。完整工程 JSON 包含模型、来源、原生文件与运行证据；完整任务包另保留历史修订、草案及任务记录。

初版支持结构化关系视图、线性带条件时序、串并联/k-out-of-n RBD 和布尔故障树。完整 SysML、任意动态图、复杂时序组合片段、P 求解器及公司工具的实机验收属于后续范围。原生方法模型需专家审阅，系统不把架构图自动等价转换成所有分析模型。

## 数据和计算口径

- `EngineeringModel.schemaVersion=1.0.0`。`entities` 是系统对象，`failureModes` 是基本事件，`views` 是显示布局；一个共享事件在多个门中引用同一个事件 ID。
- `relations / mechanisms / requirements / behaviors / cases / decisions` 共同描述设计，`sourceRefs` 指向不可变材料；材料 `segments` 保留定位。当前按材料关联，参数逐字段的精细引用可通过后续 schema 演进补齐。
- 故障率明确为 `FIT` 或 `1/h`；恢复时间为小时。任务可靠度使用 `exp(-λt)`；二态独立维修稳态可用度使用 `1/(1+λ·MTTR)`，不能代替不中断概率。直接 `probability` 字段表示失效概率；RBD 编译为成功概率，FTA 保持失效概率。
- BDD 解决共享事件的布尔计算；不同基本事件仍采用独立假设。事件超过64、逻辑树或 BDD 预算超限会拒绝。一个部件多个维修状态不能简单相乘，需聚合参数或 CTMC。
- 维度案例把范围外事件条件化为“不发生”；硬件/软件/网络等来源和中断/降级/静默错误等影响可同时筛选，分类结果不能相加。
- 机制不直接乘一个通用“改善系数”。静态作用需明确 `effects` 及 `conditions`，冲突映射被拒绝；未提供定量映射的协议机制只保存为待验证约束，不计入计算收益。
- `contentHash` 覆盖整个保存模型；`semanticHash` 排除视图和决策记录。运行同时保留修订、两种摘要和完整输入。摘要用于完整性核对，不是来源真实性签名。

## AI 集群工程建模样例

运行 `pnpm verify:engineering`，无需额外运行时。样例使用合成参数，依次运行：

1. 双协调器 RBD 与 FTA，确认成功概率和失效概率互补。
2. 单协调器 RBD，与双协调器在相同 100 小时任务窗口比较。
3. 双协调器稳态运行可用度，与存储快恢复措施比较；只将存储 MTTR 从 1 小时缩短至 0.1 小时，保持源 FIT 不变。
4. 记录引用真实运行的设计决策、保存任务资产、复用并导出模型与证据。

主流程的“可用度”仍按专家训练评估口径计算，扣除保存、回滚、污染等损失；这里的协调链路任务可靠度/运行可用度是明确区分的辅助指标，不能代替主指标。fencing 仅保留为待验证设计约束，没有执行协议验证，也不为其生成定量收益。

已保存的历史方法、原生输入和结果可以查看、导出和导入；未注册的方法显示不可运行，不能重新排队。不会自动修改旧快照或删除用户数据。旧安装脚本已移除，本地既有的 `.local-runtime/tlc` 目录是可手动删除的旧工具缓存。

## 内网已有工具接口

管理员通过 `REMAP_ENGINEERING_TOOLS` 指定本地 JSON 配置文件，工具不能通过 HTTP/Agent 注册命令。参见 [配置示例](../examples/engineering-loop/tools.example.json) 和[真实 BDD CLI 示例](../examples/engineering-loop/bdd-cli-adapter.mjs)。将示例中的 Node 与脚本路径改为实际绝对路径。

接口统一为 `describeCapabilities / validateInputs / execute`。支持：

| 模式 | 输入 | 输出 |
|---|---|---|
| CLI | 固定程序/固定参数，独立目录，标准输入 ToolInput JSON；不使用 shell | 标准输出一个 ToolResult JSON；标准错误用于诊断 |
| HTTP | 向管理员 URL POST ToolInput；遵守现有运行策略，不跟随重定向 | ToolResult JSON；超时/输出上限适用 |
| 文件交换 | 从案例导出 ToolInput，包含原生文件和 `metadata.inputHash` | 用户导入 `{ "inputHash": "原输入摘要", "result": ToolResult }`，摘要必须匹配 |

```json
{
  "files": [{"name":"Model.p","content":"原生模型内容"}],
  "scope":"检查范围与假设",
  "timeoutMs":60000,
  "metadata":{"modelId":"model-id","revision":1,"caseId":"case-id","inputHash":"..."}
}
```

```json
{
  "engine":"内部工具实际名称",
  "version":"实际版本",
  "verdict":"inconclusive",
  "completed":false,
  "scope":"本次执行实际覆盖范围",
  "metrics":{},
  "trace":[],
  "diagnostics":["工具未完成验证"],
  "rawOutput":"完整原始日志",
  "artifacts":[{"name":"Model.p","content":"本次原生输入"}]
}
```

`verdict` 为 `computed / satisfied / violated / inconclusive`。确定结论必须 `completed=true`；未知必须 `false`。P 和内部工具显示自己的名称及状态，没有安装时不产生伪造结果。手工文件结果和跨包导入证据分别标记 `user-imported`、`package-imported`，不能通过实时运行接口重放它们来冒充原工具。

## Agent 集成和真实验收

MCP 工具：`engineering_schema / engineering_models / engineering_model_get / engineering_materials / engineering_propose / engineering_proposals / engineering_validate / engineering_run / engineering_tools`，运行结果由已有 `run_status` 读取。工程决策同样通过完整模型草案提出；确认、导入结果、保存任务资产为用户操作，不暴露自动确认工具。

提案 `model.sources` 推荐使用 `[{"id":"已导入材料ID"}]`，由服务端补齐原文和文件，不要求模型复写 base64。完整来源若被改写会被拒绝。Agent 上下文以服务端已保存模型为准，任务令牌与模型不能跨任务使用。模型提供商错误会显示安全诊断，不返回响应凭据。

真实模型验证使用本机已有提供商配置和合成材料：

```powershell
# OPENCODE_MODEL 仅控制该进程；请使用本机订阅实际可用的模型。
$env:OPENCODE_MODEL='zhipuai-coding-plan/glm-5.3'
node --import tsx scripts/verify-engineering-loop.ts --agent
```

当前默认验收不调用模型提供商。只有显式加 `--agent` 并已配置本机提供商时才测试真实 Agent 提案；无密钥时不能把工具流程通过称为模型验收通过。此前模型调用记录属于历史证据，不替代本版验证。

证据保存在 Git 忽略的 `artifacts/engineering-loop/verification-agent.json`、`agent-messages.json`、`agent-proposal.json`、`engineering-model.json`、`verification-tools.json` 与浏览器截图中。实际 Agent 提取与专家编写的原生分析模型明确分开；人工接受由验收驱动模拟。本轮不代表真实 AI 集群参数校准、专家签认、P 或公司已有工具验收，也不代表协议性质验证。
