# 审核工作台与报告体验复核

这轮复核针对“计算链路能运行，但平台和交付报告仍显粗糙”的反馈。功能测试通过不代表界面、解释与工程适用性已经验收。

## 检查发现与改动

| 发现 | 改动 |
| --- | --- |
| 专家审核与 V4 六阶段流程堆叠，页首仍标记 V4 | 显式区分两种口径，默认打开事件与机制审核；V4 流程保留独立入口 |
| Agent 长期占据大半页面，未连接时尤其影响参数阅读 | 审核模式按需展开 Agent，评估区使用完整可用宽度 |
| 机制只有复选框，参数和 FIT 更新主要靠手写 JSON | 增加机制作用说明、中文数值表单、带来源和证据类型的事件更新编辑器；保留批量 JSON 入口 |
| 审核草稿切页或刷新后丢失 | 将审核草稿随任务设计保存，运行结果另行冻结；草稿不改变旧 V4 的设计输入版本 |
| 审核模式同步给 Agent 的摘要仍引用 V4 参数 | 摘要按当前口径选择参数，并明确完整审核草稿的读取位置 |
| 结果以表格为主，无法快速判断目标缺口 | 按所选规模展示区间目标判断、基线/组合产出、新增正确小时、目标差值 |
| 机制收益难以联系到原始损失 | 展示六项损失的基线/组合对照、按基线损失排序的故障事件；保持公共保存开销独立 |
| 导出报告缺少专家示例中的交互 | 自包含 HTML 增加规模摘要切换、事件类型/文本筛选、机制明细展开、打印入口 |
| 主评估与 Shapley 用不同样本量，数值差异容易误解 | 明确各自轨迹数及 Shapley 本批次总增益，不将两批结果强行对齐 |
| 筛选后的表格可能在打印时漏行 | 打印恢复全部事件行、展开机制明细，原始 JSON 快照留在 HTML 中供追溯 |

## 核对原则

- 所有摘要和图形从本次实际结果生成；不编造“最优措施”或现场达标结论。
- 区间下限达到目标、区间上限仍低于目标、区间跨越目标三种情况分别解释。
- 事件损失排序不等于措施实施收益排序；Shapley 保留负贡献。
- 中断观测更新不缩放未提供的静默、亚健康先验；此次不更改仿真引擎与模型口径。
- 桌面及 390px 手机布局实测，表格使用局部滚动。

## 使用范围

审核仍是独立条件评估，不替代 V4 六阶段的人工作业确认。内部中断数据、全系统静默检出覆盖、DP/step 可行性和工程成本需要后续实测校准；GLM 实际鉴权与云端外部访问入口需要在相应环境独立验证。报告摘要的规模切换只切换摘要区，后续章节明确展示各自范围，完整逐事件库采用请求选定规模。
