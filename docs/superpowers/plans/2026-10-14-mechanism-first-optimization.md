## 问题与完成范围

上一轮将参数候选后的损失缺口按局部比例换算成 FIT，再以 1、1/2、1/4、1/8 收紧。该路径没有实际机制支撑，产生约 99.55% 的全库 FIT 降低要求。本轮完全移除这条自动路径。历史结果继续可读；历史 allowFitTargets=true 不再触发自动收紧，显式逐事件 FIT 输入仍保留来源。

- [x] 默认源 FIT 固定。H-SDC-SCREEN 仅在适用 SDC 事件中按 eligibleShare × success × reduction 改变残余发生率；专家单点 reduction=25% 是工程目标，非实测全硬件降幅。
- [x] 纳入用户提出的全系统 SDC 覆盖率99.5%、即时发现0.5秒、保存阻塞0.5秒；补充基础中断/亚健康检测、恢复成功和失败路径、完整弹性/全局恢复、漏检兜底和新增校验开销的明确工程边界。
- [x] 识别专家 ABFT 的99.5%是同一算子子集中的95%主检出+90%条件补漏；不当作全系统证据，不自动重复叠加ABFT。
- [x] 全局与局部恢复分别计账；HCCL通信重建只改善适用局部弹性路径，不能给全局恢复记同一收益。
- [x] 按规模比较检查点周期；先用第一轮Shapley建议重要度形成AGREE物理损失预算，预算超额参与候选排序，最终由独立仿真判断达标。
- [x] 对象预算换算为“每事件允许等效损失秒数”，不换算FIT降幅。报告同时给出物理损失路径、保存阻塞反解、恢复平均损失预算和剩余缺口。
- [x] 来源采用P编号与独立段落，区分用户要求、专家单点方案、平台探索假设。常用目标直接显示，补充目标折叠。
- [x] 保存分规模周期并可重放推荐方案，修改参数不回到第一步；六阶段和第一轮现状保持不变。
- [x] 第二轮逐用途、逐索引SHA-256派生种子，排除第一轮和其他用途的种子。修复使用连续LCG状态作为种子导致轨迹相移相关的问题；归因集合按固定因子顺序构造，避免Shapley插入顺序改变同一组合的值。

## 方法与来源

专家材料：`references/新可靠性机制库-单点量化交付包/新可靠性机制库-单点量化.json`、`mechanism-details.cjs`。AGREE依据沿用HAC-D user manual §7的经典形式及有限窗口损失预算适配。

第一轮六项措施固定。第二轮比较用户检测/保存目标、有界恢复改进、额外漏检兜底三类方案，并比较局部链路恢复、管理面连续性、SDC筛查、恢复分类和HCCL局部通信重建。扩展适用比例100%、成功率95%、未提供开销暂按0均为明确探索假设。默认新增检测和复核另预留0.01%吞吐开销；必须用实际测量替换。

完整弹性/全局恢复30秒、漏检兜底1小时等是平台提出的待论证边界，不冒充专家单点实测。HCCL通信60→15秒对应原总恢复180→135秒，不能证明完整恢复30秒。

AGREE给出允许损失与优先级，不唯一决定物理参数。物理路径预算、对象预算和Shapley责任账是三个视角，不相加。保存预算反解 `s/(τ+s)≤B_save/T` 只约束保存；必须同时满足回滚和其他损失。稀有SDC漏检采用保守暴露量辅助筛选，不替代仿真值。
