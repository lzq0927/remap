# AI 集群样例操作与验收

2026-10-14。主要入口为「可靠性设计与评估」，使用专家 2026-10-09 评估模型。TLC 执行器、前端创建入口、原生样例、安装脚本和 Java 容器依赖已移除。

## 六阶段主流程

新建任务后选择「AI 训练集群」，按固定导航逐步确认：

| 阶段 | 要完成的工作 | 样例检查点 |
|---|---|---|
| 可用度目标 | 选择规模、窗口、目标和采样档位 | 1 万/10 万/20 万/50 万卡对应 99%/95%/90%/80%；1000 卡仅作参考曲线 |
| 故障模式 | 按对象和 hard/slow/sdc 分类查看 FIT、占比、来源 | 18 类对象、54 个模式；总占比之和为 1，每种故障类型的类内占比之和也为 1 |
| 可用度分配 | 分配六项损失预算；按需启用对象目标分配 | Equal、ARINC、AGREE、Availability 为目标约束分配；Availability 换算 FIT 需要恢复时间 |
| 可靠性措施 | 确认源 FIT 改进目标和检测、恢复措施 | 默认 SDC 检测、更频繁检查点、重放、进程恢复、弹性恢复、快速检查点六项；硬件降 FIT 需显式输入或载入分配目标 |
| 计算与权衡 | 运行评估，对照无措施、单项及组合，审阅收益分摊和独立复核 | 参数核对默认折叠；框图展示各对象 FIT 及损失改善；推荐仅适用于已计算范围 |
| 验证与交付 | 审阅输入、假设、目标差距及报告，记录交付确认 | 导出 HTML、Markdown、JSON 与离线 ZIP；确认交付不等于宣称已达标 |

首次体验可选择「快速试算」：128 条主场景轨迹、64 条贡献与独立复核轨迹。正式报告采用默认「专家复现」档位，主场景 4000 条。两档计算口径一致，精度与计算量不同；低采样结果只用于试算。

修改参数后从最早受影响的阶段重新确认：目标→第一步、故障 FIT→第二步、分配→第三步、措施→第四步、采样→第五步。更早的人工确认保留；旧结果保留为历史，不冒充新输入结果。

「可用度」沿用专家训练口径，扣除保存、回滚、污染等损失，计算公式未因改名改变。源 FIT 与检测恢复收益分开处理；Shapley 分摊组合收益，不代替目标分配，也不代表物理恢复次序。

## 可重复验收

完成项目依赖安装后执行：

```bash
# 云端 Bash 先 source scripts/cloud-env.sh；Windows 使用已安装的 pnpm。
pnpm verify:ai-cluster
pnpm verify:engineering
```

`verify:ai-cluster` 使用真实 API、队列和求解器走完六次确认，覆盖五规模曲线、54 个故障模式、默认六项机制、四个需求规模的 Shapley、敏感性分析、推荐独立复核及报告 ZIP。默认快速试算；添加 `--expert` 可使用完整专家采样。产物在 `artifacts/ai-cluster/`，包括 `verification.json`、HTML、Markdown、完整 JSON 和 `ai-cluster-report.zip`。脚本使用隔离任务，不修改已有用户任务，也不调用模型提供商。

`verify:engineering` 是辅助结构建模验收：比较单/双协调器的任务可靠度，验证 RBD 与 FTA 互补，再比较保持 FIT 不变、将存储 MTTR 从 1 小时降到 0.1 小时的运行可用度，最后保存决策、导出并复用证据。产物在 `artifacts/engineering-loop/`。该样例使用合成参数，不能代替整集群主流程；fencing 约束仍待验证，不产生定量收益。

桌面和手机回归：

```bash
pnpm exec playwright test tests/e2e/availability-workflow.spec.ts tests/e2e/engineering.spec.ts
```

六阶段界面截图在 `artifacts/availability-workflow/`，工程建模截图在 `artifacts/engineering-loop/`。测试覆盖固定导航、分类故障表、对象 FIT 分配、采样勾选排版、框图、折叠层次、报告以及修改参数后继续流程。

## 数据边界

中断类的具体占比（含 CORE-hard）待内网数据校准；缺少的亚健康、静默数据继续标记为外网先验。现有对象收益框图不假设未知的物理串并联关系；真实拓扑可在「系统建模」中补齐后进行辅助 RBD/FTA 分析。没有明确成本时，推荐不宣称经济最优；样例通过验收也不代表所有规模均达到目标。
