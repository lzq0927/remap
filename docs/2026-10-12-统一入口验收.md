# “可靠性设计与评估”统一入口验收

## 最终行为

主导航、页面标题和浏览器标题统一为“可靠性设计与评估”。新任务默认专家审核口径；删除“事件与机制审核 / 设计确认流程”两个并列入口，保留目标、证据、预算与措施、参数、计算与权衡、验证与交付六阶段。

“高级设置 → 历史模型 → 评估模型”保留 V4 兼容复核。切换模型保留各自草稿，改变当前评估输入后重新确认；不会创建两套必须顺序完成的流程。旧任务按原保存模型恢复，包括没有 activeAssessment 字段的早期 V4 任务；不会静默转换其目标、参数、输入版本或历史结果。新任务的旧 `view=workflow` 链接也不再开启第二入口。

历史列表、结果卡片、HTML/Markdown 报告根据**原运行**标注“专家审核口径 / 历史模型 V4”及指标标识。模型版本、输入摘要和结果仍来自原快照，JSON 导出保持原始运行结构。默认专家口径保留最后干净检查点；V4 的期末污染整任务清零规则未改变，不能直接混比。

查看、下载、重放历史实验均无需切换当前模型。重放留在“实验与报告”，保持当前设计版本与流程关联。旧 V4 资产映射、训练字段导入和候选回代不能悄悄切回旧模型；其适用范围和所需高级设置明确提示。专家事件更新继续使用“故障与证据”入口，器件物理 FIT 不直接混入 NPU 等效业务事件率。分配工具沿用当前模型的目标和窗口。

连接探测和输入列表异步加载，不阻塞主评估表单。Agent 面板首次展开才初始化，收起后保留已打开的会话，避免隐藏面板也创建后台连接。

使用指南和 Agent 的 sd-dfr-remap 工作指引同时更新，不再默认引导到 V4，也不要求重复走两套流程。数值引擎与专家数据没有修改。
