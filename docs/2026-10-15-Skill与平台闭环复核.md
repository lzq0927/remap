# Skill与平台闭环复核

本次回到平台目标：通过清晰的故障证据、可复现的方法和可解释的方案比较，帮助用户提出可讨论、可验证的可靠性设计决策。

## 发现并修复

| 断点 | 影响 | 本次修复 |
| --- | --- | --- |
| Skill仍有旧目标和“先分配再现状评估”说明 | Agent可能提前改变现状，跳过用户想看的第一轮 | Skill 0.3统一当前目标、原六项/95%、先现状后AGREE、各轮独立结论 |
| 源Skill与本地发现副本不同步 | 拉取代码后可能仍加载旧指引 | 开发/Agent/bootstrap/显式安装共用按内容同步；任务准备递归更新参考文件 |
| MCP没有新分轮工具 | 前端可用，Agent无法完成同一闭环 | audit_plan / audit_evaluate / audit_compare，工具发现带必需参数结构 |
| Agent不能方便发现历史轮次，列表含完整大快照 | 重复评估、上下文被重复输入挤占 | run_list与存储层摘要投影，筛选分页不受旧100条列表限制，完整快照按ID读取 |
| 同步上下文缺少独立实验信息 | Agent难以对应当前讨论的计划与改进 | 注入最近运行摘要、来源与计划关联，明确生成计划不自动复评 |
| 引导对明确局部请求仍强制询问自动方式 | 使用费力、容易重复启动 | 按明确意图直接处理；真正缺失时才澄清，自动范围明确只到第一轮 |
| 发布清单遗漏新专家机制库与当前指南 | 新目录可能缺计算引用及正确操作说明 | 补齐机制交付包及分轮操作指南 |
| Linux安装包的程序文件名与查找假设不同 | 已安装OpenCode仍可能被误报缺失 | 按官方包bin声明发现程序，保留旧布局和PATH兼容 |
| 离线准备被会话迁移强制依赖原生服务 | Agent不可用时连Skill/MCP准备也失败 | 准备配置与迁移解耦，只在有历史绑定且原生服务可用时迁移 |

## 与初衷的对应

- **易用**：统一六阶段，复用确认信息；独立改参不用重新确认第一轮；直接读历史运行并导出。源码、任务副本、发布内容同源。
- **易懂**：先讲目标和损失，再讲分配、措施、结果和未满足项。第一轮总贡献与改进增量分别解释；规划预期和实际复评分别显示。
- **智能协作**：Agent读取任务真实输入、机制库和实际结果，能生成分配、执行明确改进、比较与交付。工具输出有界，避免聊天承担状态存储。
- **逻辑严密**：AGREE为工程责任与允许损失分配，组合仿真检查总目标；不自动降低FIT，不强求物理路径子预算，不合并不同规模最严要求。置信区间跨目标保留待复核。
- **通用与可追溯**：核心Skill/MCP不依赖某个聊天模型；架构建模、来源、性质、辅助求解和专家审阅保留各自语义。输入及每次运行不可变，具体产品仍需自己的传播模型、参数校准和工具适配。

## 验证范围

真实MCP客户端已执行完整六阶段自动第一轮至待审核、AGREE计划、仅99.5%对照、独立载入计划评估、横向报告与离线包描述；检查第一轮及流程状态保持不变、计划不冒充评估、跨任务引用被拒绝。另覆盖105条历史的摘要分页、旧Skill升级且不重复改写相同文件。

桌面1440px与手机390px覆盖第一轮、手改、分配、复评、对比与交付；Agent阶段产物和人工确认边界也经浏览器检查。原生OpenCode 1.18.35已实际加载任务Skill、连接任务MCP、保持任务会话隔离并发现登记的GLM提供商。

这些验证没有请求GLM推理服务，也没有把规划参数或模型结果当产品实测。AI训练默认链路已有完整样例；其他产品仍需各自架构/故障/传播数据。未提供的工程约束、成本和共因假设需要继续校准；主规模方案不能替代其他规模的独立达标结论。
