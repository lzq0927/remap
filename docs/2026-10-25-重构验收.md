# 架构与可靠性工作台重构验收

本记录对应[实施计划](superpowers/plans/2026-10-25-remap-workbench-rebuild.md)与[方法核对](2026-10-25-架构与分配方法核对.md)。验收对象是软件行为、方法实现和界面；测试中的低采样快速结果不作为集群工程结论。

## 本轮交付

- 使用用户 PDF 第 2–4 页原图核对 Atlas 950：1024 NPU 模组、16 计算柜、64 L1、16 L2、8 平面及 IO/参数面/存储面。正文的 2 互联柜与原图的 4 互联柜作为两个有来源的参照保留。
- 重画代表性超节点架构，支持千卡、1024 参考点、万卡、十万卡、二十万卡和五十万卡。区域关联数量、等效 FIT、目标/当前可用度、损失、故障和机制；未知器件指标显示待补充。
- React Flow 按当前层及直接子层浏览，提供展开、面包屑、小地图、缩放和详情；热力矩阵与跨规模目标、损失、贡献、改进视图共用计算快照。
- 增加独立命名的经典 AGREE 条件式，保留 NASA 近似式和历史兼容标识。有限窗口损失预算明确为工程适配，Shapley 只作为贡献和优先级证据。
- 增加 L2 平面组网辅助验证：单 L2、同柜双 L2、跨柜双 L2，BDD 与独立蒙特卡洛稳态抽样交叉核对，显式容量门、机柜共因、随机种子和 Wilson 区间。
- 正式运行冻结网络输入及结果；导出读取该快照，不重新抽样。旧结果没有网络计算时说明尚无结果，不补造历史计算。演示参数明确标识，不改变主流程事件率或达标结论。
- 报告复用架构和诊断读模型，增加逐规模改进摘要，长来源移入可展开证据区；同步更新 `sd-dfr-remap` skill。

## 工程边界与后续数据

1. 逐器件原始 FIT、维修时间、完整端口/BOM、单路径容量与共因数据仍需项目输入；图上的 NPU 等效事件 FIT 不能冒充器件 FIT，也不能重复乘设备数量。
2. 分层可用度是业务损失责任投影，父层汇总子层，不是独立模块可用度连乘。主流程继续保留干净检查点的业务指标口径。
3. 网络辅助模型目前覆盖 L2 与机柜共同故障域，不包含完整网络路由、L1、光模块、倒换瞬态和动态维修。完整拓扑的动态可靠性评估需要更细模型。
4. 本文记录实施与验收，提交状态以 Git 历史为准；本轮未部署。截图和测试产物位于本工作区 `artifacts/`，该目录不纳入 Git。
