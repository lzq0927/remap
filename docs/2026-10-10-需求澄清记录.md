## 4. 指标分配与正向评估

建议拆成两类接口：

- 目标分配：输入总目标、结构、基线参数和约束，输出子目标、假设、可行性及分配依据。
- 正向评估：输入具体结构与参数，计算系统结果，验证分配方案是否达到目标。

| 方法 | 定位 | 核心条件与边界 |
|---|---|---|
| Availability 串联合成 | 独立串联系统的可用度正向合成；结合权重形成反向分配策略 | 必须满足独立状态及系统成功条件；仅有乘积公式不能唯一决定子目标 |
| Equal | 同类预算的均分基线 | 明确均分的是失效率、对数可靠度预算还是其他预算，不能直接除以百分比目标 |
| ARINC | 按基线失效率比例分配目标失效率 | 传统方法假定独立串联、恒定失效率与相同任务时长；不能直接替代含恢复的训练产出模型 |
| AGREE | 考虑复杂度、重要度和工作时长的可靠性分配 | 记录具体公式版本及近似条件；重要度不是任意主观权重，冗余与低重要度情形需要检查适用性 |
| 基于模型的约束搜索 | 对复杂恢复、共因故障和训练任务指标推荐机制与参数组合 | 通过同一正向模型校验，纳入参数边界、机制前置条件、成本及不确定性 |

在独立串联系统中，可用度满足 `A_sys = ∏ A_i`；一种明确的分配规则是令 `-ln(A_i)` 按权重分配，均分时为 `A_i = A_target^(1/n)`。这是带明确条件的策略，不应宣称适用于所有结构。

多个方法对比应固定系统边界、指标定义、输入版本和评估配置；分别生成候选方案，再回代同一模型，比较达标情况、改进要求、机制成本和稳健性。不直接平均不同方法的结果。

### 产品目标驱动的闭环

产品级目标与适用规模 → 子系统/组件目标与故障、恢复预算 → 架构及机制候选方案 → 正向求解 → 达标差距与改进建议 → 验证与报告。

区分产品目标、基线预测和候选方案预测。规模变化的目标表由用户确认或通过有明确假设的规则生成；不能直接按卡数推算可用度。独立同质故障源、任一故障都中断作业且机制不变等假设下，可以近似按卡数缩放中断事件率，但恢复及有效产出仍需单独计算。

数值核对：在二态稳态模型下，若 MTBF 定义为平均正常运行时间，`A = MTBF / (MTBF + 平均不可用时长)`。万卡 99% 与 31.5 小时对应平均不可用时长约 19.09 分钟；十万卡 94.3% 与 3 小时对应约 10.88 分钟。保持前者恢复时间、将 MTBF 按十倍规模缩为 3.15 小时，得到约 90.83%，因此两组示例不能仅由等比例失效率推算互相推出。以上只核对该二态口径，不用于替代训练正确有效产出模型。

### 主指标口径确认后的设计约束

- 整体目标以正确有效产出率表达；MTBF 是影响目标的输入参数或分配要求之一，不与该目标简单等价。
- 在统一理想产出基准上建立互斥损失账本，将整体允许损失预算分解到停机、保存开销、降速、局部容量损失、回退和未恢复错误等项。因果归因与会计分账分开。
- 预算进一步映射到子系统和组件的故障模式、影响域、检测覆盖及延迟、恢复成功率及耗时、检查点与弹性策略等可执行设计要求。
- 同一故障或共享机制跨越多个预算项时，必须由联合模型回算，不能将机制收益简单相加，也不能把 AGREE/ARINC 直接作用于整个产出率百分比。
- 正向计算应先检查目标可行性上界。专家最新基线为计算 300 秒、阻塞保存 4 秒，仅该开销就将长期无故障产出率限制在 `300/304 ≈ 98.684%`；因此按该理想产出基准要达到 99%，必须改变检查点开销或策略等条件。有限窗口精确值由模型计算。
- 专家目标分析区分平均正确有效产出与单月达到阈值的比例；产品验收要指定采用哪种统计判据。均值置信区间不等于单次任务结果覆盖范围。
- 当前已指定严格交付策略：`A = E[P_correct(T) × I_clean_end(T)] / W_ideal(T)`，期末污染导致的其他正确进度判废单列到账本。“保留最后干净检查点”仅能作为另外命名、版本化的策略；不能将更换交付判据产生的提升归因为可靠性机制收益。
