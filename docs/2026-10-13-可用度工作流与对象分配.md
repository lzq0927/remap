# 可用度工作流与对象分配

新专家任务统一使用“可用度”作为展示名称。内部指标仍为 `training.retained-clean-progress`：固定窗口内最终保留的正确进度除以窗口时长，停机、保存、回滚、污染、降速和局部容量损失的计算均未改变。辅助指标“运行可用度”仍单独展示。默认万卡、十万卡、二十万卡、五十万卡目标仍为 99%、95%、90%、80%。

## 六阶段

| 阶段       | 主要操作                                                             |
| ---------- | -------------------------------------------------------------------- |
| 可用度目标 | 确认规模、窗口、分规模目标与评估口径                                 |
| 故障模式   | 按对象类型和故障类型筛选；展开查看 FIT、总占比、类内占比、影响及来源 |
| 可用度分配 | 先按实际故障对象分配独立子模型目标，再分配六项互斥损失预算           |
| 可靠性措施 | 选择硬件降 FIT、已部署基线和新增检测恢复措施，预览覆盖框图           |
| 计算与权衡 | 运行按钮优先显示；采样、复核和详细参数在“参数核对”中按需展开         |
| 验证与交付 | 核对冻结输入、组合收益、置信区间和建议，人工确认并导出报告           |

固定导航保留上一步和下一步。结果的“本次输入、组合与计算口径”分为范围、故障、分配、措施、采样五个有编号的区块；只有较长的详情继续折叠。

## 参数修改后的续接

服务端比较两份经过校验的设计输入，确定最早受影响的阶段。修改采样数量或种子，从第五步复核；修改措施、恢复能力或硬件目标，从第四步复核；修改分配，从第三步复核；修改故障证据，从第二步复核；修改目标、规模、窗口或模型口径，从第一步复核。

用户继续时，未受影响的连续人工确认可以沿用。新执行使用新的 `executionId`，前序记录注明来源；计算结果和交付确认不沿用，旧运行仍保留自己的输入版本。浏览已确认步骤不会重复签认。Agent 的“自动完成”不能升级为人工确认，也不能通过 `resume` 冒用人工确认。输入无效或缺少可比较的历史快照时保守复核。

## 对象 FIT 与分配

当前专家参考库包含 18 类对象、54 个故障模式。中断 / 亚健康 / 静默的外网总量先验为 96.6% / 2% / 1.4%；各对象并非都按这三个比例拆分。页面显示当前数据实际计算的占比。内网仅更新某些中断事件时，其余事件的 FIT 保持原值；没有静默观测不代表静默 FIT 为零。

对象分配使用当前库的 NPU 等效 FIT。卡数为 N 时，集群事件率为 `FIT × N / 10⁹`；任务率分配完成后，目标 FIT 要除回 N。页面、输入快照与报告使用同一单位。对象或卡数变化后必须刷新并复核分配，服务端拒绝使用过期的对象率。

- Equal / ARINC：分配独立串联、指数失效假设下的任务可靠度，按普通乘积回合成。
- AGREE：按复杂度与重要度分配近似任务可靠度，按 `∏Rᵢ^Eᵢ` 回合成，不能用普通乘积核对。
- Availability：分配独立串联运行可用度的对数预算。转换为 FIT 还需要显式的二态平均修复时间，`λᵢ = (1/Aᵢ - 1)/MTTRᵢ`。

这些子模型约束与主流程的可用度分开。独立串联运行可用度或无失效完成概率不能直接证明含保存、回滚和污染的主指标达标。检测与恢复的责任通过损失预算、机制能力和正向仿真落实，不能把任意训练损失直接套用串联公式。

点击“将分配 FIT 载入硬件改进目标”才会生成目标草稿。分配值作为上限，已低于上限的对象不调高 FIT；按本对象当前故障构成拆分，标记为方案假设，仍需工程论证。Availability 缺少修复时间时允许查看子目标，但不能据此生成硬件 FIT。自定义子系统的 `/h` 和 FIT 保留子系统小时单位，不能直接载入 NPU 事件。

## 框图与决策

第四步可预览对象 FIT 与候选措施覆盖。评估完成后，在结果的“可靠性框图”切换基线、单项、组合，以及提供硬件目标时的“目标 FIT＋所选机制”方案。每类对象显示三类基线 FIT、源 FIT 变化及两套方案实际损失；公共保存损失单列。可用度和达标判读来自同一份冻结仿真，1000 卡参考点不作需求达标判断。

框图是故障对象到检测恢复、可用度的影响视图。当前未提供完整物理拓扑，不虚构对象之间的独立串并联或冗余关系；需要实际拓扑求解时使用“系统建模”的 RBD/FTA/BDD 功能。当前参考库支持逐项替换既有故障证据；新增内部子对象或故障模式需要扩展事件定义、映射和相应校验。

检测恢复措施一般不改变源 FIT，而是改善损失。框图的改善数值来自完整方案比较，不能把多个单项收益相加。Shapley 继续用于组合贡献分摊，物理恢复顺序仍由恢复链决定。建议组合标明筛选规模与独立复核结果，不把单个规模的通过扩展到所有规模。

HTML 报告加入同源框图与对象改善表，Markdown 保留对应数值表。报告中的对象分配目标 FIT 同样换算为 NPU 等效小时。历史运行保留原指标标识、输入、来源和数值；历史 V4 仍在高级设置中。

### 本次验收结果

- 类型检查、ESLint、生产构建通过，专家 4000 条轨迹数值回归通过。
- 单元、接口和专家测试累计覆盖 295 个通过用例，5 项条件性跳过。全量运行后，报告单位等后续修改又完成相应的定向回归，未把跳过项计为通过。
- 浏览器全量及修复后定向回归共覆盖 53 个通过用例；原生 OpenCode 的 2 项可选浏览器测试未执行。最后的桌面/手机六阶段与固定导航 8 项均通过。
- 两项离线报告 `file://` 导航被本环境托管 Chromium 策略阻止，错误为 `ERR_BLOCKED_BY_ADMINISTRATOR`。下载、解包和 JSON 内容一致性此前步骤通过；另用独立回环 HTTP 静态服务在 1440px/390px 验证了报告、框图、故障筛选及相邻 JSON 下载，无平台 API 或外部资源请求。这不替代用户本机双击文件的验证。
- 报告增加框图后，表格增强脚本已兼容不含 table 的图容器；故障筛选、长来源详情、打印与分规模目标均重新通过浏览器回归。
