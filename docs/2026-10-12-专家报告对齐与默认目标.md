# 专家报告对齐与四规模默认目标

## 用户确认的指标

99% / 95% / 90% / 80% 用于**正确有效产出率**，沿用专家审核的“期末保留正确进度 / 窗口理想产出”口径。运行可用度仅扣除全局停机，独立展示。

| 单作业规模 | 默认正确有效产出目标 | 专家参考中断 MTBF |
| --- | --- | --- |
| 万卡 | 99% | 约 30h |
| 十万卡 | 95% | 约 3h |
| 二十万卡 | 90% | 约 1.5h |
| 五十万卡 | 80% | 约 0.6h |

新任务默认同时比较四个规模。切换审核卡数时保留各规模编辑过的目标，选中规模的标量 target 与 targets 中对应目标保持一致；非本次规模的草稿目标不会进入求解输入。旧任务和历史结果不自动改成新目标。

中断 MTBF 由 `10⁹ / (卡数 × 中断 FIT 总量)` 计算，当前专家基线中断总 FIT 约 3333.333。目标是需求，不从 MTBF 推导，也不通过修改 FIT 强行拟合目标。未来更新 CORE-hard 等事件 FIT 后，总占比、类内占比、中断 MTBF、损失与机制收益重新计算；未提供的静默/亚健康保留外网先验。新增“本次基线数据更新记录”保留参考 FIT、本次 FIT 和占比，完整来源可展开查看。

新任务 sensitivityMode 默认为 `expert-reference`：覆盖率与 step 采用静默检测＋step 情景，弹性暂停采用弹性单项情景，与专家一致。`selected-combination` 保持用户已选措施并按启用机制扫描。每组记录情景、当前参数、比较基准和损失，参考单项曲线不冒充所选组合达标结论。

旧请求未指定 sensitivityMode 时保留原来的五点静默扫描，旧结果仍按原快照导出。数值模型标识更新为 `review-retained-progress.v3`，恢复引擎没有修改；新增的是默认要求、扫描编排、自动核查和报告解释。

## 证据范围

自动检查仅验证本次模型内数值，不把专家旧报告的“通过”记录复制为本次认证，也不声称已验证内网原始数据。报告中的比例和 Core 占 SDC 比例来自冻结输入；不把原先 96.6% / 2% / 1.4% 或 85% 写死为内网更新后的结论。

Markdown 展开全部已计算规模的事件/机制表，HTML 以离线内嵌表格模板切换，打印当前选择的规模并展开来源与机制。HTML 图表、参数表和 JSON 仍取同一运行快照。
