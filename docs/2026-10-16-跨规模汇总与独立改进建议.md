# 跨规模汇总与独立改进建议

汇总按需求规模从小到大展示，AI样例为万卡、十万卡、二十万卡、五十万卡；参考点另列。只改变展示顺序，保留原输入、种子、计算口径和历史结果。

主线为：系统架构 → 各层目标分解 → 总体目标与可用度差距趋势 → 故障模式库的细分差距 → 损失时间横柱 → 贡献排名变化 → 分规模AGREE分配 → 各自的可靠性措施与参数要求 → 用户独立复评。

工作台支持选择上级节点查看子层预算，选择任一节点查看趋势。总体图显示各规模自己的可用度目标、现状与95%均值区间；子层图显示允许损失和实际损失，不能冒充模块自身可用度。父子预算汇总，逐层不重复相加。

细分故障差距按各规模单独排序。叶层预算按该叶层FIT份额细分到事件，仅作诊断参照；故障损失、公共保存和检测开销保持互斥。横向堆叠柱可按损失环节、子系统或故障类型查看，所有柱共用小时刻度并标记预算。

贡献排名汇总到一张排名变化图，并列名次保留；贡献值曲线及矩阵保留负值和原95%区间。现状与改进增量分别解释，不用排名变化宣称统计显著性。

“按各规模分别生成改进建议”调用/audit/plan-scales，以同一冻结第一轮分别规划各规模，得到不同措施配置和参数要求。计划集合可独立导出，曲线上的不同规划点对应不同配置；规划均值不是正式复评或产品实测。选择具体规模建议后再载入、修改与单独评估，记录planRunId与planCards，检查原任务中其他规模的效果。不会合并最严参数、自动评估或改写现状。

MCP0.3.1新增audit_plan_scales，Skill0.3.3说明图表读法与计划选择。单规模audit_plan及既有独立评估继续兼容。总规划工作量受限，参考点、重复规模、无贡献证据或跨任务计划在调度前拒绝。

可运行`node --import tsx scripts/verify-scale-summary.ts --expert`复用此前已保存的4000条现状结果，并独立生成各需求规模建议。若没有已有4000条样例则完整计算现状。验证报告与截图位于artifacts/scale-summary。
