# 指标分配与 Agent 流水线实施计划

**目标：** 从当前任务的输入实际计算专家审核报告，并支持指标分配选择和自动/交互执行。

**架构：** 分配计算独立于 Agent 和界面；流水线服务管理任务版本、阶段产物、真实求解与报告；可移植 Skill 经 MCP 调用服务，本地 OpenCode 保持原生界面。

**技术：** TypeScript、Fastify、React、MCP SDK、现有离散事件求解器与 allocation 包。

## 科学口径与设计

- 专家原报告已有有限窗口仿真、互斥损失账、机制失败回退、全子集 Shapley、敏感性与守恒复核。事件 FIT 分布是输入先验，不是产品目标分解。
- 正确有效产出目标分解为六项互斥损失预算，支持均分、基线损失比例、手工权重。预算在候选措施计算前确定；基线比例使用本次基线样本并保存来源。
- Equal / ARINC / AGREE / Availability 用于明确的任务可靠度或稳态可用度子模型，独立设置目标，保存合成检查与多方法比较。禁止把训练产出目标直接当作串联任务可靠度。
- 分配不改写源 FIT；措施必须有覆盖、检测、恢复或独立硬件 FIT 参数；最终产出与 Shapley 使用真实正向仿真。
- Skill 首先询问自动执行或交互协助。自动模式允许服务完成阶段，保留真实输入快照，生成报告后停在最终审核；自动完成不冒充人工确认。交互模式沿用逐阶段确认。
- 输入变更使旧执行失效；重复启动、取消、版本冲突和失败应可见；不得跨任务引用结果。

## 验收边界

完整浏览器回归 34 项通过；另运行本地 OpenCode 原生界面验收通过。最终预算界面、手机宽度、真实自动报告与手工流程再次复测 3 项通过。类型、ESLint、前端构建、MCP 构建通过。

最终完整单元/专家/集成回归 46 个测试文件、233 项测试全部通过（包含原生 OpenCode、内网配置加载、MCP 与 SciPy 数值求解）。原始专家万卡基线 4000 条轨迹回归通过；本次没有重新执行完整 766000 条轨迹的专家原始全规模生产采样，不把快速集成验收宣称为完整原报告逐数值复现。

本地 OpenCode 1.18.35 实际发现任务 Skill、原生命令、MCP 和 GLM Provider 模型声明；未调用外部大模型。初始模式提问和后续自然语言交互由 Skill 约束，需在已配置的模型上实际验收，不能把连接测试当作模型执行质量证明。自动编排仅支持专家训练审核口径；其他产品和历史模型继续使用交互模式。

自动报告中的“已完成”与“已人工确认”有不同状态；最终审核不可由 Agent 代替。输入改变、用户取消和错误执行 ID 的取消请求均有集成验收。额外修复取消顺序：先校验执行 ID，再取消对应计算，避免旧页面误取消新任务的运行。

最终补充后台 Skill 派发及重复请求保护，Agent 接口增加可选 AbortSignal 以便服务关闭时释放启动请求。9 项相关集成/适配测试通过，类型、规范和最终前端构建通过；未执行外部模型推理。
