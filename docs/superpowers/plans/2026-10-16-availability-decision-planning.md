# 可用度分配与决策优化实施计划

参考 HAC-D v3.7（ad75799）的分配、规划与多规模报告；保留 ReMAP 专家审核引擎、各规模自己的目标、六阶段确认及分轮独立评估。

## 目标与边界

现状输入冻结后，沿“架构与故障损失 → 分配责任 → 工程能力边界 → 候选组合 → 参数要求 → 独立复评”解释建议。Shapley 是组合贡献，工程优先级不是经典AGREE的系统失效条件概率。功能层级不能自动解释为独立串联RBD。所有新推断注明版本、来源、搜索范围与假设。

## 实施步骤

1. 梳理并扩展规划请求：分配方法、重要度/复杂度/可改进性、措施工作量、参数锁定和有来源的工程边界、保守参数情景。缺失证据显式保留，历史请求继续兼容。
2. 实现工程责任预算方法对照（均分、现状比例、AGREE适配、可改进性、最小努力及成本权衡），注明适用指标；保留经典任务可靠度/串联可用度子模型。接入真实的复杂度设置，输出权重来源和敏感性。
3. 在现有正向仿真规划上增加有界组合比较、必要性复核、工作量—收益前沿和代表方案。参数与机制均尊重锁定/适用条件；不能将全选当作上界，未找到可行解不能宣称证明不可达。
4. 计算检测、恢复、保存等单类杠杆的可达性试算，展示当前边界及仍需改善的量。对目标/先验参数评估可配置保守情景；均值区间、情景范围和窗口达标概率分别解释。不自动启动正式第二轮。
5. 将代表配置固定后分别计算需求规模的曲线；添加现状/方案成对损失柱、贡献热力图及采用标记，保留排名折线与所有负值。图表必须对应冻结计算值，未完成评估用明确的规划标识。
6. 报告增加各规模决策摘要、可行性、权重来源、备选方案、参数边界及待验证证据；来源放技术明细。前端提供通用规划约束编辑和方案选择；MCP/Skill同步。
7. 运行数学边界与组合交互测试、API冻结/计划选择测试、报告一致性测试；桌面1440px与手机390px走通完整流程。用4000条冻结现状样例生成新规划报告、截图和验证记录。

## 验收标准

- 第一轮所有数值、种子、目标和历史结果不变；生成建议不产生正式改进运行。
- 预算守恒；固定责任优先扣除；能力边界冲突明确说明；经典AGREE与工程适配方法不混淆。
- 人工参数要求不被搜索悄悄覆盖；工作量评分不是货币成本；保守幅度有记录，未填资料不伪装实测。
- 非加性组合、负贡献、前置条件、同阶段重叠与正常态开销均由原模型计算；限定搜索不宣称全局最优。
- 每条跨规模曲线采用同一配置；每个规模使用自己的目标；不从四个点外推最大支持规模。
- 规划和正式独立评估明确区分，选定备选方案后仍由用户另行点击评估。
- 类型检查、Lint、相关回归与桌面手机浏览器验证通过，图表与导出报告可读且可追溯。
