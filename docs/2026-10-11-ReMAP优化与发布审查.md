# ReMAP 优化与发布审查

本轮由用户授权直接实施：统一名称、修复流程导航滚动固定、审视功能与解耦、将通用成果推送至指定 GitHub 仓库。保留本机数据与原始工作计划，不对外发布企业资产。

## 本轮设计与修改

名称统一为 ReMAP（Reliability Modeling and Analysis Platform），侧栏入口为“可靠性设计工作台”。流程导航成为主区域直接子元素，仅导航固定，执行记录与过程产物正常滚动。动态测量导航高度，步骤跳转预留相应空间，覆盖桌面和手机布局。侧栏导航样式限定在侧栏，避免影响流程导航。

API 的 Agent 集成统一在 `apps/api/src/agent-integration.ts` 组装。`buildApp({agentIntegration})` 允许管理员注入其他实现，路由使用 `WorkspaceAgentPort`，保留任务会话绑定、隔离与人工授权。默认实现仍为本地原生 OpenCode；当前 LUI 原生面板使用 OpenCode 的展示与模型配置，需要替换界面时另做 UI 集成验收。求解器、共享 Skill 和 MCP 无需依赖该原生 UI。

开发界面代理默认跟随 PORT，显式 VITE_API_TARGET 仍可覆盖。发布增加暂存区路径/凭据检查，原始工作计划写入忽略规则。本机诊断路径从通用指导文档移除。

| 文件与真实输入         | 任务目录实时读取、JSON/CSV/XLSX、文本/PDF文字、模型提取与确认、企业映射接口；扫描 PDF OCR 与任意图片结构还需验收                            |

| 科学可信度             | 方法假设、单位、证据、种子、摘要、区间及数值回归；尚无行业盲测对标，不能宣称超过业界                                                        |
| 持续演进               | 本地轨迹、运行与用户反馈记录；定期技术调研、自动优化、弱模型成功率统计运营仍待扩展                                                          |

## 发布与验证

提交通用源代码、文档、模板、公开参考与合成回归输入；不提交密钥、本机配置、任务数据库、真实输入、导出资产、原始《系统可靠性工作计划.md》、运行日志或依赖目录。目标仓库为 `https://github.com/lzq0927/remap.git`。以目标仓库现有 main 为父提交发布，保留其历史，不推送本机开发历史或强制覆盖远端。

验证范围：类型与 lint、全量数值/集成测试、原生 OpenCode 元数据与任务 MCP、桌面/手机滚动与步骤定位、完整浏览器流程、软件与独立 MCP 构建、迁移验收、提交清单与敏感内容检查。最终实际结果见发布提交说明和本机 `artifacts/remap-publication-validation.json`；公司侧待验范围见 [内网开发指南](内网开发指南.md)。

2026-10-11 最终结果：在基于目标仓库 main 的独立源码工作区，完整发布验收的 9 项检查通过；199 项自动化测试、16 项浏览器测试通过。515 个 npm 依赖使用缓存离线安装、0 下载，桌面/手机固定导航和修改 API 端口后的开发代理验证通过。待提交树的 209 个文件检查通过，11 个专家参考文件保留来源摘要。检查覆盖待发布树与目标仓库祖先，不推送本机旧开发历史。

该验收使用显式提供的本机原生 OpenCode 与 Python/SciPy 运行时，不包含真实模型推理，也不等同于第二台物理机器或公司网络验收。首次独立源码验收缺少 SciPy 导致 CTMC 测试失败，按部署说明补齐运行时后重新执行全部检查通过；因此 Git 与 npm 依赖包不能替代完整运行时供给。

后续优先顺序：通用故障传播模型及金标准 → 机制依赖/成本约束 → 参数不确定性/真实校准 → 企业身份权限与平台集成。每一项应单独确认输入契约与验收案例。
