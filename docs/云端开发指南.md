# ReMAP 云端开发

GitHub Codespaces提供仓库内 `.devcontainer` 自动初始化方案，创建、私有端口预览和Agent配置见[Codespaces开发指南](GitHub-Codespaces开发.md)。

云端用于通用代码开发；公司内部代码、配置和真实任务资产继续留在内网。Git 同步已提交的代码，运行目录及聊天存档不随 Git 同步。

## 初始化

需要 Bash、Node.js 24 或更新版本、pnpm 11.25.0、Python 3.12 或更新版本，以及 Chromium 所需的 Linux 系统库。在项目根目录执行：

```bash
bash scripts/setup-cloud.sh
source scripts/cloud-env.sh
```

初始化使用锁文件安装 Node 依赖（包括 OpenCode），按 CTMC requirements 安装项目专用 Python 依赖，并运行 bootstrap 和 doctor。优先使用 PATH 中已有的 Chromium；也可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定可执行文件。没有系统浏览器时才下载 Playwright Chromium，下载域名需由环境网络策略允许。已有 `.env` 和 Skill 会保留；重新运行会按声明版本更新依赖。若需指定 Python，可设置 `REMAP_PYTHON` 为解释器路径。

`cloud-env.sh` 将 pnpm 缓存、OpenCode 配置和状态、浏览器放在被 Git 忽略的 `.local-runtime` 下，不修改 HOME 或代理设置。每个新终端都需重新 source。可用绝对路径 `REMAP_CLOUD_RUNTIME` 指定另一个可写位置；切换位置会使用另一套工具状态与凭据。

受限云端中，安装依赖和 Git 操作需由执行工具授予联网权限；运行本地 HTTP 服务及其集成测试也可能需要该权限。若默认沙箱报代理连接失败或 socket 权限错误，先检查执行权限，不要清空代理或关闭 TLS 校验。浏览器如报告缺少系统库，需通过环境管理员支持的安装方式补齐；脚本不自动改动系统软件。

## 启动

在两个均已 source 环境脚本的终端中分别执行：

```bash
pnpm agent
```

```bash
pnpm dev
```

默认 OpenCode、API、开发界面分别监听云端机器的 `127.0.0.1:4096`、`127.0.0.1:4178`、`127.0.0.1:5173`。这些地址不是本地电脑地址；浏览器访问需要平台支持的预览或端口转发。此流程不创建公网入口。

云端默认关闭 OpenCode 自动更新、模型目录在线获取及默认插件加载，以便在受限网络下启动和验收。实际模型的地址和凭据需在此环境单独配置；服务健康、Skill 加载与 MCP 握手通过，不代表真实模型推理已经验证。

## 验收

保持 OpenCode 服务运行，在已 source 的终端执行：

```bash
PYTHONPATH="$PWD/solvers/ctmc/.python-deps${PYTHONPATH:+:$PYTHONPATH}" \
  python3 -m pytest solvers/ctmc/test_solver.py -q
RELIABILITY_REQUIRE_CTMC=1 TEST_OPENCODE_URL=http://127.0.0.1:4096 \
  pnpm verify:release
```

完整验收包含 doctor、类型检查、lint、自动化测试、Web/MCP 构建、浏览器测试、发布包和中文/空格目录迁移；结果写入 `artifacts/release-validation.json`。设置 `TEST_OPENCODE_URL` 会启用真实已安装 OpenCode 的 Skill/MCP 集成检查，不调用模型。使用自定义 Python 时，为上述命令指定相同解释器，并设置 `PYTHON_EXECUTABLE`。

## 日常迭代

开始前 fetch 并检查与目标分支的差异；每项开发使用独立分支，验证后提交和推送，通过 PR 合入主分支。本地拉取后重点检查 Windows、交互体验和离线交付。密钥、`.env`、`.local-runtime`、`data`、依赖及验收产物均不提交。

云端文件存在不等于已有远端备份。阶段性成果及时提交推送，重要运行数据按其许可范围另行备份。

## GLM 连接配置

云端可配置模型，但不会自动继承本机 OpenCode 的密钥。新任务使用原生提供商 ID `zhipuai-coding-plan`、国内 Coding Plan 地址 `https://open.bigmodel.cn/api/coding/paas/v4` 和 `glm-5.3`，使“连接提供商”保存的凭据与选择的模型归属一致。普通按量 API 和 Coding Plan 不要混用。已有自定义 `bigmodel-coding` 配置保留；请在模型选择器改选已连接的原生智谱 Coding Plan，或为自定义提供商单独配置匹配凭据。

密钥通过当前云端 OpenCode 的官方连接界面或环境 Secrets 配置，不能写进 Git、任务包或聊天。环境变量方式可使用原生提供商识别的 `ZHIPU_API_KEY`，修改后重启该环境的 OpenCode。仅显示“已连接”或健康检查通过不能证明实际 Authorization 已通过；最终以一次最小模型请求成功为准。本轮未取得真实密钥，因此未验收 GLM 推理。外部浏览器仍需云平台预览/端口转发；localhost 链接只能在云端机器内访问。
